# 해야 할 일

앞으로 할 일과 실제 클라이언트에서 확인할 것을 둔다. 끝난 항목은 지운다.
운영자 도구는 [admin.md](tech/admin.md)(`/sgadmin give <ID>`, `/sgdebug hunt [몬스터]`, `/sgdebug ui <기계>` 등)를 쓴다.

## 할 일

### 기능
- 공동 호스트(권한 등급 `cohost` 는 DB 에 있다).
- 도관 면 설정의 우선순위·자기 공급·필터·레드스톤 제어.
- 통계 화면의 분 단위 막대 그래프, 정지한 기계 옆 표시(파티클).
- 처음 쓰는 UI 안내: 계정마다 본 UI 를 기록하고(DB 마이그레이션) 처음 열 때만 안내 줄을 보인다.
- 도감 책 아이템(들고 쓰면 도감, 블록을 보며 쓰면 그 블록의 쪽). 재료로 종이(섬유로도 만든다)를 쓸지 정한다. 바닐라 책·지도 조합법은 아직 어느 연구도 열지 않는다.
- 손에 든 도구의 내구도 "현재/최대" 글자(HUD).
- 모바일(pocket) 창고 화면에도 모두 꺼내기·모두 넣기 버튼 줄(`sg_quick.side_bar`).
- 달성 토스트를 HUD 제목 표식으로 그릴지 검토(지금은 엔진 토스트).

### 정리
- Sky Gear 이름 변경 세이브 변환(`content/skygear/migrate/namespace.go`와 그 테스트)과 그 호출(`cmd/skygear/main.go`)을 모든 서버가 한 번씩 돌린 뒤 지운다. 데이터 폴더의 `skygear-namespace.done` 플래그와 `<데이터 폴더>.before-skygear` 사본도 함께 지운다.
- `UseOnBlock` 의 두 번째 확장 모드 검사 `expand.guardSide`(HIGHEST)는 일할 때가 없다. 확장 모드의 클릭은 `expand.guard`(LOWEST)나 화면을 여는 아이템의 구독자가 이미 취소한다. 구독자를 지우거나 옆 칸 검사가 의미를 갖게 고친다. 지우면 `order.golden` 과 `handler-use.golden` 에서 그 줄이 빠진다.
- 훅에 남은 결정([extension.md](tech/extension.md) "구독자와 취소", "훅과 블록·아이템의 메서드"). 정하면 플레이어가 보는 동작이 바뀌므로 테스트를 더하고 장면 골든을 다시 기록한다.
  - 서버가 멈출 때 이차원에 있던 플레이어가 돌려받는 메뉴 아이템은 옛 이름 그대로다. `screens.menuItem`(LOWEST)이 `dimension.joined`(LOW)보다 먼저 돌아 이름을 고친 뒤에 소지품이 돌아오기 때문이다. 1초 안에 고쳐지는지, 입장 때 고칠지 정한다.
  - 섬 끝줄에 놓인 기계의 바깥쪽 면에서는 요정의 모래시계가 쓰이지 않는다. 옆 칸 가드(`island.guardSide`)가 그 클릭을 막는다. 그 면에서 기계 창이 열리지 않는 것과 같다. 그대로 둘지 정한다.
  - 이차원에서 죽으면 `death` 업적도 센다(진 판마다 한 번). 세지 않으려면 `achievement.death` 가 `core.InArena(e.P.Position())` 인 죽음을 건너뛰게 한다.
  - 폭발 공격은 피해를 주지 못했을 때도(맞은 직후의 무적 시간) 사냥꾼을 밀어낸다. 근접 공격은 피해가 들어갔을 때만 민다. 맞출지 정한다.
  - 취소가 필요 없는데 취소하는 구독자: 공중에서 연 메뉴 아이템(`Use` 의 `screens.menuItem`), 흙·잔디를 두드린 막대기(`handwork.stick`). 취소하지 않게 바꾸면 장면 골든의 `cancelled=` 가 달라지고, 막대기는 섬 가장자리에서 옆 칸 가드의 "섬 밖" 팁이 함께 뜬다.
  - `stick_other` 는 아무도 취소하지 않은 클릭만 센다. 막대기로 누른 다른 블록을 모두 세려면 `handwork.stickOther` 에 `core.HandleCancelled` 를 주고 `core.Takeover` 조건을 단다(섬 밖, 서랍 메뉴, 도관 판, 작물을 누른 것도 센다).
  - `Jump` 의 `elevator.up` 은 모드에 붙잡힌 플레이어도 태운다. `elevator.down` 처럼 `core.Takeover` 조건을 달지 정한다.
  - 섬 가장자리의 원목을 섬 밖을 향한 면으로 누르면 `handwork.gather`(NORMAL)가 섬유를 떨군 뒤 `island.guardSide`(HIGHEST)가 클릭을 취소해 원목이 벗겨지지 않는다. 되풀이할 수 있다. `handwork.gather` 가 끝까지 간 클릭만 받게 옮길지 정한다.
- 티어 안 순서 가드(`TestTierOrder`)는 장면의 결과, 업적 카운터, 장면의 플레이어가 든 아이템을 견준다. 채팅·팁·소리·패킷, 장면이 닿지 않는 상태는 보지 못한다. 첫 접속 때 메뉴 아이템이 소급 요정 가루를 덮어쓰던 문제(`TestFirstJoinKeepsBackfilledDust`)는 그런 장면이 없어서 빠져나갔다. 인벤토리를 건드리는 접속·퇴장 구독자마다 장면을 더한다.
- `Join` 의 `screens.board`(MONITOR)는 `dimension.joined`(LOW) 뒤에 돈다. 서버가 멈출 때 이차원에 있던 플레이어의 퀘스트 비용 줄이 처음부터 되돌린 소지품을 센다.
- 같은 MONITOR 안에서는 채팅 순서가 설치 순서를 따른다(`achievement.place`·`conduit.place`·드래곤 알림, `playSeconds` 와 수집 보상). 기록을 MONITOR 로 옮기면서 업적 메시지가 다른 구독자의 메시지 뒤로 간 곳이 있다(`Death`, `BlockPlace`). 순서가 중요한 메시지가 있으면 한 구독자로 묶는다.
- MONITOR 가드(`TestMonitorSubscribersDoNotShape`)는 구독자 함수 본문만 읽는다. 도우미 안의 취소는 장면 테스트에서 `Emit` 이 잡지만(추적 중일 때 패닉), 도우미 안에서 이벤트의 포인터에 쓰는 경우와 포인터를 변수에 옮겨 쓰는 경우는 보지 못한다. 지금의 MONITOR 구독자는 읽어서 확인했다. 가드를 넓히거나 MONITOR 구독자에 읽기 전용 이벤트를 넘긴다.
- `TestHuntClear`(`content/skygear/dimension/dimension_test.go`)와 `TestKitAndLevels` 가 `TestHuntFails` 와 같은 시간 의존 방식이라 `-race` 에서 `TestHuntFails` 처럼 불안정해질 수 있다. 같은 방식으로 시간에 기대지 않게 고친다.
- `-race` 에서 `TestPinUse` 가 가끔 테스트에만 있는 데이터 경합을 보고한다. 동기 테스트 월드가 미뤄 둔 일을 월드 큐 밖에서 돌리기 때문이다(`fairy.wander` 와 `placeAt`·`Teleport`). 테스트 월드가 미룬 일을 월드 큐에서 돌리게 하거나, 시나리오가 그 일이 끝나기를 기다리게 고친다.
- `machine.Register` 는 부르는 기능이 그 종류의 `Owner` 인지 확인하지 않는다. 다른 기능이 남의 종류를 등록해도 `TestKindOwners` 와 골든은 통과한다. 커널이 지금 설치 중인 기능 이름을 알려 주면 막을 수 있다. 기능 패키지의 테스트는 `core.Install` 없이 `coretest.Setup` 으로 설치하므로(`netstore/keys_test.go`) 그 경우를 어떻게 볼지 먼저 정한다.
- `debug_ui.go` 의 `windowKinds` 에서 `k != machine.KindTinker` 는 이제 뜻이 없다. 제작대에 클릭 훅이 있어 앞 조건에서 이미 빠진다. 지운다.
- 패널 줄을 내지 않는 종류(서랍 테두리·제작대·보구 제작대, `machine.NoLines`)는 시간 가속 줄도 내지 않는다. 전에는 가속 줄이 붙었다. 이 종류들은 전력을 쓰지 않아 모래시계가 듣지 않으므로 손으로 고친 세이브에서만 차이가 난다. 가속 줄을 살릴지 정한다.
- `dimension` 은 `fairy` 가 등록하는 아이템(`sgitem.FairyDust`)을 `fairy` 를 임포트하지 않고 지급한다. 루트가 둘을 함께 링크해서 동작한다. `TestHuntRecords` 가 이 때문에 루트에 남아 있다. 요정 가루의 등록을 `sgitem` 이나 `dimension` 이 닿는 곳으로 옮기거나 `dimension` 이 `fairy` 를 임포트하게 한다. 등록 순서가 바뀌면 클라이언트 골든을 다시 기록해야 한다.
- 한 프로세스에서 테스트를 두 번 돌리면(`-count=2`) `netstore` 의 `TestTerminalDepositGoesToTask`("craft hooks not set")와 `wire` 의 `TestWire` 가 실패한다. 테스트가 바꾼 전역 훅을 되돌리지 않기 때문이다. 되돌리게 고친다.
- 기능 패키지로 옮긴 핸들러 테스트는 자기 기능만 설치한 채로 돈다. "취소되지 않는다"·"가져가지 않는다" 같은 단언은 다른 기능의 앞 단계가 이벤트를 건드리지 않는다는 것까지는 더 증명하지 않는다(`TestPlantingRecordsCrop`, `TestPlateClicksWithAnythingInHand`). 조합된 순서는 루트의 `order.golden` 과 시나리오 골든이 고정한다. 이 두 경우를 시나리오 골든에 더할지 정한다.
- 테스트 도우미 `droppedItems`(루트 `helpers_test.go`, `handwork`)와 `droppedKeys`(`tinker`, `farm`)는 이름만 다른 같은 함수가 패키지마다 복사돼 있다. `coretest` 로 올려 하나로 합친다.
- `coretest.Setup` 을 `core.Install` 보다 먼저 부르는 테스트 바이너리는 같은 구독자를 두 번 등록해 패닉한다. 지금은 그런 바이너리가 없다. `Install` 이 이미 설치된 기능을 건너뛰게 할지 정한다.
- 옛 세이브 고정 테스트(`TestOldSaveLoads`, `testdata/save/oldsave.zip`)가 덮지 않는 저장 항목이 있다. 아이템의 NBT(내구도·인챈트·이름·도구 개조), 분쇄기 말고 다른 기계의 블록 엔티티, 나무 말고 다른 호퍼, 서랍 컨트롤러와 저장 네트워크 디스크, 갑옷·보조 손, 상태 문서와 SQLite 테이블이다. 다음에 아이템 번호가 바뀌는 변경을 하기 전에 고정 파일을 넓힌다(넓힌 파일은 그 변경 전 코드로 기록한다).
- 아이템 레지스트리 패킷 안의 항목 순서는 등록 순서를 따르고 어느 골든도 고정하지 않는다. 번호는 항목마다 명시돼 있어 순서에 기대는 클라이언트 동작은 알려진 것이 없다. 실기에서 문제가 보이면 순서를 고정한다.

## 실기 확인

### 화면 공통
- 모바일: 모든 창(326×166 이하)과 탭·컨트롤 막대가 화면 안에 드는지, 터치 스크롤·검색칸 입력·스크롤 막대 끌기.
- 터치 툴팁: 처음 탭하면 툴팁만, 두 번째 탭에 눌림. 뒤로·쪽 넘김·탭은 한 번에. 툴팁 글자 크기와 화면 끝 처리.
- 애플 기기: Ore UI 한글이 네모 없이 보이는지, 창이 가운데 서는지, 바닐라 Ore UI(HUD·바닐라 화면)가 그대로 뜨는지. 안 되면 `/uidebug` 디버그 줄을 스크린샷으로 받는다.
- 한글과 영문·숫자가 섞인 줄이 같은 높이인지(`web/oreui/src/text/Rich.tsx`).
- Ore UI 서버 리소스(`/sgdebug oreres`): Windows 에서 `packet style`·`packet blob: script`·`pack link` 를 다시 본다. 모바일(Android, iOS)에서 같은 표가 나오는지. 결과는 [oreui-probes.md](tech/oreui-probes.md) 표에 적는다.
- Ore UI 입력 이벤트(`/sgdebug oreinput`): Windows 에서 Alt 를 누르지 않고 마우스 버튼별 `button`, `dblclick`, `contextmenu`, 휠(`dx`·`dy`), 포커스, 입력칸의 `input`·`composition*`(한글 IME)이 찍히는지. 모바일에서 터치·누른 시간·포인터 이벤트, 게임패드 연결·버튼·축. 결과는 [oreui-probes.md](tech/oreui-probes.md) 에 적는다.
- Ore UI 부분 갱신: 바뀐 칸만 바뀌고 스크롤 자리·툴팁이 남지 않는지(정수 추출기, 도움말, 통계, 연구, 도감).
- 카드 메뉴(한 줄 4장), 쪽 넘김, 창 입체선, 회색 테마 글자 대비, 입력칸.
- `slotdeco` 팩이 바닐라 인벤토리·상자 화면을 그대로 두는지(문제 시 `[ResourcePack] SlotDeco = false`).
- JSON UI(연구 위키 기준으로 고친 것): 콘텐츠 로그에 `Invalid expression`·경로 키 오류가 없는지. 슬롯 단계 표식(1~6)이 상자·기계·인벤토리 칸에 그대로 그려지는지(`modifications` 의 배열 `value`). 있는 것만 넣기가 작은 상자·큰 상자·세로·스크롤 창·기계 창에서 같은 아이템이 있는 칸만 옮기는지. 버튼 이름 툴팁이 창 위 왼쪽으로 열려 376px 폭·큰 GUI 배율에서도 화면 안에 드는지. 검색칸이 빈칸·공백만일 때 칸을 어둡게 하지 않는지. 기계 정보 아이콘이 누를 때 깜빡이지 않는지. 영어 클라이언트 검색칸이 `Search` 인지.
- HUD: 포켓 프로필 터치에서 하트·갑옷·배고픔·공기 방울·탈것 하트가 핫바 위에만 한 벌 보이고 종이 인형은 왼쪽 위에 남는지(경로 키 `ignored`). 터치에서 왼쪽 위 줄·퀘스트 창이 화면 오른쪽 끝에 맞는지. 다른 사이드바 보드로 바꿨다 돌아올 때 줄이 다시 만들어지는지. WAILA 가 상자·화로·호퍼·양조대·기계에서 `__waila:` 글자 없이 가운데 위에 서는지, WAILA 글자(`font_scale_factor` 0.6)가 여러 GUI 배율에서 고르게 보이는지.
- 클래식 UI 프로필의 휴대폰: 기계 창과 모두 꺼내기·넣기 버튼 줄을 탭 한 번으로 쓰는지, 버튼 툴팁(`$hover_state`)이 터치에서 어떻게 보이는지.
- 영어 클라이언트: 아이템 이름(`en_US.lang`), 폼·도감·WAILA·연구·발전과제 글이 좁은 칸에서 끊기지 않는지.
- Ore UI 클라이언트 번역: 일본어 등 서버 카탈로그에 없는 언어와 영어 클라이언트에서 도감·연구·실험실·통계·분실물 화면의 아이템 툴팁과 도관 면 이름이 클라이언트 언어로 나오는지, 세이브 목록의 만든 날이 기기 날짜 모양인지(`web/oreui/src/text/localize.ts`). 번역 명령이 Promise 를 돌려주면 대체 글만 보이므로 그때는 `tr` 를 고친다.
- 메뉴 화면 종류마다(메뉴·카드 메뉴·입력칸·아이템 칸·검색 칸·면 설정·퀘스트 판·로비 화면) 열고 닫아도 접속이 끊기지 않는지. DDUI 화면만 쓸 때 클라이언트가 폼 응답(`ModalFormResponse`)을 보내면 Dragonfly 가 세션을 끝낸다.

- 세이브 입장·로비 이동 뒤 몇 초 안에 움직일 수 있는지.

### 초반 자원
- 섬 보호 범위, 청크 원점 근처 섬의 시작 위치.
- 크룩·누에: 크룩 그림(Fabrico)과 손에 든 모양, 나뭇잎을 캐는 속도가 클라이언트와 맞는지(되돌아오는 블록 없음), 내구도 줄어듦, 묘목·누에 드롭 체감. 누에를 나뭇잎에 쓸 때 소리와 손 동작. 익힌 누에가 화로·훈연기·모닥불에서 구워지는지, 먹는 동작과 배고픔이 차는 양.
- 누에 나뭇잎: 밤에 주변 잎과 같이 어두워지는지(`alpha_test_single_sided` + 주변광 가림), 맞닿은 잎과 면이 깜빡이지 않는지, 단계 그림이 잎처럼 비쳐 보이는지, WAILA 의 "고치 생성률 N%"가 6초마다 10%씩 올라 1분에 100%가 되는지, 서버를 껐다 켠 뒤에도 이어지는지(예약 틱 저장), 26.11.7 세이브의 감염 잎이 누에 나뭇잎으로 이어지는지, 100%가 될 때 주변 잎에 모두 번지고 나무 전체로 퍼지는지, 나무를 베면 누에 나뭇잎과 그 바깥 잎이 함께 시드는지(가위로 놓은 잎은 남는지), 벌목기·불·폭발과 함께 쓸 때, 크룩·맨손 실 개수 체감.
- 체: 실 메쉬로 일곱 금속 조각, 메쉬 조합, 빈손으로 웅크려 메쉬 빼기, 체 모델(막대 깜빡임, 메쉬 색, 상태 199개), 드롭률 체감.
- 배럴: 물·용암 시간, 호퍼·도관 입출력, 점토, 안에 들어서기·내용물 높이, 나무 양동이.
- 돌 배럴 용암(열원별 빠르기, 양동이로 퍼고 붓기, WAILA), 조약돌 생성기.
- WAILA 에서 불(영혼 불 포함)을 조준하면 아이콘 자리에 부싯돌과 부시가 그려지는지.
- 손으로 놓은 배럴(참나무·돌)을 옆면·위에서 조준하면 WAILA 가 아래 불이나 바닥 대신 배럴을 보이는지, 여러 개를 놓은 뒤에도 그런지.
- 분쇄 블록과 망치, 마녀의 물과 네 가지 섞기.
- 나무껍질 섬유: 화로·훈연기·용광로 연료 칸에 손으로 끌어 넣어지는지(`minecraft:fuel` 컴포넌트), 막대기만큼 타는지, 호퍼·아이템 도관이 옆면으로 연료 칸에 넣는지, 연소 발전기 WAILA 의 연소 표시. "종이" 연구 뒤 2×2 칸(인벤토리 포함)에서 섬유 4개로 종이 2개가 나오는지, 사탕수수 종이 조합법도 함께 열리는지.
- 도구 자동 들기: 캐기 시작한 순간 바뀐 도구의 속도로 그 블록 캐기가 이어지는지(처음부터 다시 누르지 않아도 되는지), 핫바·위 칸 아이템이 바로 보이는지.
- 마법 식물: 교차 모델, 개화 텍스처, 수확, 멀리서 깜빡임.
- 엘리베이터: 점프·웅크리기 순간이동이 한 번만 일어나는지, 점프하던 힘이 도착 뒤에 남지 않는지, 16색 윗면·옆면 텍스처.
- 취소된 클릭(섬 확장 모드, 섬 밖, 메뉴 아이템)이 유령 블록을 남기지 않는지. 사용 버튼을 누르고 있어도 메뉴와 텔레포트석이 한 번만 열리는지.
- 압축 블록: 제작대에서 9개 → 1개, 1개 → 9개 조합이 연구 뒤에만 보이는지(레시피 책 포함), 칸의 단계 점·희귀도 색, 임시 텍스처 10종이 서로 구분되는지, 놓고 캐는 속도와 드롭, 건축 지팡이로 놓이는지.
- 섬 확장 압축 조약돌 지불: 왼쪽 위 판의 "가진 것"이 압축 블록을 더한 값과 압축 몫을 보이는지, 낱개 조약돌이 먼저 빠지는지, 큰 단계를 깨면 거스름(낮은 단계 + 조약돌)이 인벤토리에 바로 보이는지, 인벤토리가 가득할 때 거스름이 분실물 보관함에 들어가고 알림이 뜨는지.

### 에너지·도관·기계
- 발전기·도관·분쇄기 라인, 에너지 게이지와 멈춤 표시.
- 태양광 발전기: 하늘이 트인 곳에서 낮·새벽·저녁·밤에 따라 WAILA 의 RE/t 와 햇빛 %가 바뀌는지, 요정 마법의 비·눈과 해 고정(낮·저녁·밤)이 바로 반영되는지, 위에 블록을 놓으면 1초 안에 "하늘이 가려져 멈춤"이 뜨고 유리는 막지 않는지. 실제 섬에서 하늘 판정(`tx.HighestBlock`)이 맞는지(투명한 커스텀 블록, 표시 엔티티 위).
- 수력 발전기: 폭포·흐르는 물 옆에서 면 수와 물살 %가 바뀌는지, 수원만 닿으면 "고인 물만 닿아 멈춤"이 뜨는지, 물을 치운 뒤 1초 안에 멈추는지, 발전기를 놓아도 물길이 이상하게 막히거나 끊기지 않는지.
- 두 발전기의 임시 그림(태양광 윗면 판, 수력 파란 띠)과 작동 띠, 단계 테두리, 생산 통계 화면의 발전기 수·가동 수.
- 도관 모양: 팔 방향, 세 차선, 연결 변화, 100칸 이상 프레임, 선택·충돌 상자, 아이템 크기, 수평 네 방향 화살표(`tools/conduitgeo` `arrowQuad`).
- 도관 놓기·면 설정 창: 들고 우클릭, 웅크려 놓기, 카드 여섯 개 배치, 색 네모·`+` 고르기 판, 새 도관은 모든 면 꺼짐, 라운드 로빈 출력, 속도 표기.
- 기계 창: 컨트롤 막대 정보 버튼, 모두 꺼내기·넣기·있는 것만 넣기 버튼, 자동 제작기 칸과 조합법 목록.
- 있는 것만 넣기(상자·기계 창): 창고에 이미 있는 아이템만 옮기는지, 창을 열고 닫을 때 끊기는지(인벤토리 36칸 × 창고 54칸 비교 바인딩).
- 자동 채굴기·수확기·자동 체 출력과 호퍼·도관, 전기 화로·흡수기·벌목기.
- 작동 애니메이션: 작동 중에만 움직이는지, 멈추면 약 2초 뒤 돌아오는지.
- 기계 강화: 키트 사용·소리·파티클, 단계별 속도·소비·범위, 단계 테두리가 재시작 뒤에도 남는지.
- 설정 복사기: 도관 면·자동 제작기 조합법·서랍 설정 복사와 붙이기.
- 건축 지팡이: 면 넓히기·방향 제한, 되돌리기, 내구도 막대.
  - 미리보기: 놓일 블록이 레이어 1 에서 제자리·제 크기(반 블록 바닥 위, 꽉 찬 블록 옆면·윗면)로 보이고 초록 미리보기 유리가 겹쳐 보이는지, 미리보기 칸을 조준해도 선택되지 않고 뒤의 블록 면이 조준·클릭되는지, 조준을 옮기거나 화면을 돌리거나 다른 아이템을 들면 유리와 블록이 함께 사라지고 실제 블록(물이 있던 칸은 물)으로 돌아오는지(레이어 1 을 먼저 비운다), 몸이 걸리지 않는지(선택·충돌 상자를 크기 0 인 점으로 보낸다. 클라이언트가 받지 않거나 꽉 찬 상자로 다루면 Dragonfly 패치로 `enabled: false` 를 보내는 방식으로 돌아간다).
  - 철 망치 연쇄 범위: 웅크리고 철 망치로 보면 부서질 블록 위에 파란 미리보기 유리가 겹쳐 보이는지, 보던 블록을 그대로 캘 수 있는지, 웅크리기를 풀면 사라지는지. 망치·지팡이 미리보기를 번갈아 들 때 남는 유리가 없는지.
  - 원형 메뉴: 웅크리고 허공 우클릭으로 화면 가운데 뜨는지(블록을 누를 때 같이 뜨지 않는지), Windows 에서 원과 글이 잘리지 않는지, 아이템 아이콘이 보이는지, 마우스로 가리킨 칸이 밝아지고 누르면 고르는지, 휴대폰 터치, 방향키·WASD·숫자·Enter, 게임패드, Esc 로 닫히는지, 부채꼴(회전한 상자로 채움)이 틈이나 깜빡임 없이 그려지는지, 방향 제한·블록 일치를 누르면 다음 값으로 바로 바뀌는지, 크기가 화면을 너무 가리지 않는지.
- 서랍 앞면의 손에 쥐는 모양 아이템(막대기·뼈다귀·블레이즈 막대기·브리즈 막대): `/sgdebug holderpose` 로 다른 아이템처럼 평면·같은 크기로 보이는 회전·크기·위치를 찾아 `animations/item_holder.animation.json` 기본값에 적기. 다른 아이템도 비스듬히 크게 보이면 `item_holder.entity.json` 목록에 추가([drawer.md](tech/drawer.md) '손에 쥐는 모양 아이템').

### 클라이언트 데이터 이동 뒤 (Dragonfly 패치 없이 보내는 것)
- 도구 태그: 곡괭이·도끼·삽·괭이·가위가 맞는 블록을 더 빨리 캐는지(돌, 나무, 흙, 나뭇잎), 곡괭이 등급이 모자란 블록이 드롭 없이 캐지는지, 팅커 도구의 속도, 크룩·망치의 캐기 구성요소(`minecraft:digger`)가 크룩은 나뭇잎에서, 망치는 돌·조약돌에서 빨라지는지.
- 충돌 상자: 통(배럴)과 통 모양 블록에 올라서고 안으로 들어가는지, 저장망 케이블·수입기·수출기·외부 저장소와 도관 둘레에서 걸리거나 끼는 곳이 없는지.
- 뼈 보임: 저장망 블록이 연결된 방향마다 팔이 보이고 연결이 바뀌면 바로 따라 바뀌는지, 체가 모양별(메쉬 유무)·채움 단계별로 막대와 내용물이 맞게 보이는지.
- 누에 나뭇잎: 밤에 주변 잎과 같이 어두워지는지, 맞닿은 잎과 면이 깜빡이지 않는지.
- 연료: 나무껍질 섬유 등 연료 아이템이 화로·훈연기·용광로에서 타는지, 연료 칸에 끌어 넣어지는지.
- 우클릭: 허공을 누르는 아이템(텔레포트석)이 열리는지, 기계·서랍처럼 누를 수 있는 블록을 들고 누르면 블록이 놓이지 않고 창이 열리는지.
- 이차원에서 맞은 몬스터 위로 피해 숫자가 글자로 떠오르고 블록(모래 같은 것)이 그려지지 않는지.
- 서버를 끄면 접속한 클라이언트에 종료 안내 글이 뜬 채로 끊기는지.
- 명령이 내부 오류로 실패할 때: 오류 줄이 한 줄 뜨고 그 앞에 빈 줄이 생기지 않는지(클라이언트가 Dragonfly 의 명령 출력 패킷과 오류 패킷을 차례로 받는다).

### 이차원의 죽음과 공중에서 쓰는 아이템 (아직 확인하지 않음)
서버 쪽은 테스트로 확인했다. 아래는 실제 클라이언트에서만 볼 수 있고, 아직 아무도 보지 않았다.
- 이차원에서 죽었을 때 죽음 화면 없이 바로 부활하는지. 판이 시작될 때 그 플레이어에게만 `doimmediaterespawn` 게임 규칙을 보내고 판이 끝나거나 부활하면 되돌린다(`Player.EnableInstantRespawn`). 접속 도중에 받은 규칙을 클라이언트가 곧바로 따르는지, 죽고 나서 섬에 서기까지 얼마나 걸리는지 잰다.
- 클라이언트가 규칙을 따르지 않으면 판에서 질 때마다 죽음 화면이 뜬다. 그때도 판은 이미 끝났고 보상은 들어와 있다. 부활 버튼을 누르면 들어왔던 자리로 오는지 본다.
- 마지막 타격의 붉은 번쩍임과 맞는 소리, 죽는 모습이 보이는지. 부활해 섬으로 넘어오는 화면이 어색하지 않은지.
- 부활한 자리에서 청크가 오기 전에 떨어지지 않는지(부활 뒤 `instance.PlaceAt` 이 땅 위에 붙잡는다). 결과 창이 0.5초 뒤에 뜨는지.
- 판이 끝난 뒤 섬에서 죽으면 예전처럼 죽음 화면이 뜨는지(규칙이 꺼졌는지).
- 죽음 화면에서 접속을 끊고 다시 들어오면 섬에 있고 소지품이 그대로인지.
- 복사기, 건축 지팡이, 망치가 `minecraft:use_modifiers`(`use_duration` 0.05, `movement_modifier` 1)를 새로 받는다. 이 아이템을 든 공중 클릭이 서버에 오는지(전에는 오지 않았을 수 있다), 누르고 있을 때 쓰는 모습이나 느려짐이 생기는지, 망치로 캐거나 지팡이로 짓는 느낌이 달라지지 않는지.
- 공중 클릭으로 카드가 든 복사기가 비워지고, 웅크린 지팡이가 설정을 보이고, 웅크린 철 망치가 대각선 캐기를 바꾸는지. 셋 다 버튼을 누르고 있어도 한 번만 되는지(0.5초 안의 되풀이는 무시한다. 복사기는 비운 뒤라 다시 눌러도 바뀔 것이 없다).

### 패치로 남긴 것 (대체할 수 있는지 판단)
- 섬 확장 지도의 가짜 청크(`ViewFakeChunk`): 지도가 제대로 그려지고 닫으면 실제 월드가 돌아오는지, 그동안 월드 블록 변화가 지도에 끼지 않는지.
- 블록을 눌러 `Activate` 가 성공한 뒤 주변 블록 재전송: 블록을 든 채로 서랍·기계 같은 블록을 눌러도 손 앞에 유령 블록이 남지 않는지.
- `Activate` 뒤 손 아이템 다시 읽기: 서랍·배럴에 아이템을 넣을 때 손에 같은 아이템이 남아 복사되지 않는지.
- 커스텀 블록을 서버가 직접 부수기(`tickCustomBreak`): 부수는 시간이 맞고 두 번 부서지지 않는지, 계속 누르고 있어도 한 번만 부서지는지.
- 잔디 퍼짐: 빛을 막지 않는 커스텀 블록 아래의 잔디가 흙으로 돌아가는지, 바닐라 블록 아래와 같게 움직이는지.
