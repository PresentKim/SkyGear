# 도감과 JEI

도감(`/도감`, [codex.go](../../internal/games/skygear/codex.go), [codexsearch.go](../../internal/games/skygear/codexsearch.go))을 레시피 뷰어(JEI)처럼 쓰게 하는 방법과, JEI 가 수백 개 칸을 렉 없이 그리는 이유, 그것이 Bedrock JSON UI 에 주는 교훈을 정리한다.
JEI(Just Enough Items, MIT)는 소스(`Gui/src/main/java/mezz/jei/gui` 아래)를 읽어 확인한 내용만 적었고, 코드는 가져오지 않았다. "추정"이라고 적은 것은 실기로 재야 한다.

## JEI 가 렉이 덜 걸리는 이유

JEI 화면에는 아이템 칸이 수십~수백 개이고 버튼도 많지만, 위젯 객체를 그만큼 두지 않는다.

| 기법 | JEI 소스 | 내용 |
|---|---|---|
| 즉시 모드 그리기 | `IngredientGrid.draw` | 한 번 그리는 함수가 매 프레임 칸을 직접 그린다. 칸마다 컨트롤 트리·바인딩이 없고, 마우스가 올라간 칸은 좌표 비교(`getHighlightedSlot`)로 한 개만 찾는다. 호버 상자도 그 한 칸에만 만든다 |
| 보이는 쪽만 | `IngredientListRenderer.set(startIndex, list)` | 칸 객체(`IngredientListSlot`)는 화면 크기에서 나온 개수만 만들어 재사용하고, 목록의 `startIndex` 부터 그 개수만 채운다. 쪽을 넘기면 같은 칸 객체의 내용만 바뀐다 |
| 종류별 일괄 그리기 | `renderBatch` | 같은 종류(아이템)의 칸을 모아 한 번에 그린다 |
| 미리 만든 검색 색인 | `ElementSearch`·`GeneralizedSuffixTree` | 접미사 트리를 접두사(이름·모드·툴팁·태그…)마다 따로 만들어 둔다. 낮은 메모리용 `ElementSearchLowMem` 이 따로 있다 |
| 한 번만 계산 | `IngredientFilter.getElements` | 검색어가 바뀔 때만 목록을 다시 거르고(`ingredientListCached`), 아무것도 바뀌지 않은 프레임은 캐시를 돌려준다. 색인·정렬은 "더럽힘 표시"(`dirtySearchIndexes`, `sortIndexesDirty`)가 있을 때만 다시 만든다. 정렬 순서는 색인으로 미리 계산 |
| 레시피를 재료로 색인 | `RecipeIngredientRoleMap` | 레시피를 등록할 때 역할(재료·결과·촉매)별로 재료 ID → 레시피 표를 만든다. R/U 를 누르면 표 조회 한 번이다 |
| 레시피 화면 지연 생성 | `LazyRecipeLayoutList`, `RecipeGuiLogic.getVisibleRecipeLayoutsWithButtons` | 분류의 레시피 목록은 지연 목록이고, 화면에 보이는 한 쪽(`subList`)만 레이아웃을 만들어 그린다 |

정리: **칸의 수와 비용이 비례하지 않게** 만들었다. 비용은 보이는 칸 수(고정)와 검색어가 바뀐 횟수에만 든다.

## Bedrock 에서는

JSON UI 는 유지 모드다. 폼 버튼 하나가 컨트롤 트리(배경·아이템 그림·글자·호버 상자…)이고 바인딩도 칸마다 평가되므로 비용이 칸 수에 비례한다. 이 서버에서 확인한 것([json-ui.md](json-ui.md) '폼 성능'):
- 숨긴 레이아웃도 버튼을 만들면 폼이 길수록 멈춘다. 레이아웃을 숨김으로 시작해 `binding_condition: visible` 로 평가하면 열 때 멈추지 않는다.
- 연구 목록처럼 칸이 수십 개인 폼은 쪽 나누기 없이 한 화면에 두 구역으로 보여도 렉이 없다.

JEI 기법을 옮긴 규칙:

| JEI | 이 서버 |
|---|---|
| 보이는 쪽만 | 서버가 쪽을 나눈다: 도감 검색 결과 한 쪽 44칸(`codexPage`), 11칸씩 줄바꿈. 쪽을 넘기면 새 폼이다 |
| 미리 만든 색인 | `codexIndex()` 는 처음 쓸 때 한 번 만든다(창작 인벤토리의 모든 아이템 중 얻는 곳·쓰이는 곳이 있는 것, 144개 안팎, 약 20ms). 검색은 그 위에서 이름만 비교한다(`textsearch.Match`, 초성 포함) |
| 검색어가 바뀔 때만 | 검색은 입력 폼을 보내는 순간에만 돈다. 결과 폼은 그 쪽의 칸만 만든다 |
| 호버 상자 한 개 | 칸마다 상자를 두지 않고 엔진 툴팁(`hover_text`)을 쓴다 |
| 레시피를 재료로 색인 | 도감은 기계가 읽는 표(체 표·합금·정수 추출기·조합대 등)를 그대로 읽는다([10 §4](../design/10-user-flow.md)). `codexSources`·`codexUses` 가 표에서 "만드는 재료"와 "이것으로 만드는 것"을 뽑는다 |
| 지연 생성 | 아이템 도감 쪽은 누를 때 만든다. 아이템 하나의 링크는 많아야 수십 칸이다 |

## 도감의 JEI 기능

도감은 위쪽 탭 줄이 있는 창 하나다: **검색 · 체 · 가공 · 몬스터 · 식물**. 탭은 아이템 쪽까지 모든 쪽에 보여 한 번에 오간다(`codextabs.go`). `/도감` 은 손에 든 아이템 → 바라보는 블록 → 검색 탭 순으로 연다.

| JEI 기능 | 도감 |
|---|---|
| 아이템 목록 + 검색 | 검색 탭: 이름(초성 ㅊㅈㄱ 도 됨), 비우면 전체. 쪽 넘김. 첫 쪽 위에 "즐겨찾기"와 "최근 본 아이템"(JEI 의 즐겨찾기·기록). 목록에는 스카이기어에서 만나는 아이템만 있다(`codexRelevant`): 게임 자체 아이템, 게임 표가 받고 내는 것(연구 비용, 체·마법 체, 기계, 시뮬레이터, 웨이브, 식물, 장비 재료), 연구가 여는 레시피의 결과, 그리고 그것들을 만드는 재료(열린 조합대 레시피와 화로를 따라 원재료까지. 화로에서 같은 것이 되는 재료가 여럿이면 이미 목록에 있는 것, 없으면 참나무·변형 없는 것 하나만: 목탄의 재료로 다른 나무들, 주괴의 재료로 심층암 광석이 따라오지 않는다)와 화로·분쇄기가 그것들로 만드는 것. 게임이 쓰지 않는 바닐라 아이템(물약 변형 등)은 없다 |
| R(얻는 곳) | 아이템 쪽의 **얻는 법** 보기(머리 줄의 조합대 칸): 그 아이템을 만드는 레시피를 카드로 그린다. 조합대 레시피는 실제 조합대처럼 3×3 틀에 재료 → 화살표 → 결과(개수), 기계 레시피는 재료(한 줄 4칸) → 화살표 → 결과(한 줄 6칸), 체는 메쉬 → 화살표 → 드롭과 확률(블록은 위 줄에서 고른다)(JEI 의 Ex Nihilo 체 분류처럼). 같은 기계의 카드는 머리 줄(틀 없는 작은 기계 아이콘과 노란 이름, `ui.MiniCell`) 하나 아래에 모이고, 다른 기계의 머리 줄 앞에는 빈 줄이 하나 있어 출처가 나뉘어 보인다. 화살표는 재료 바로 뒤, 결과는 그 뒤다. 기계 표에 없는 손작업(막대기로 잔디·흙 우클릭 → 돌멩이, 망치로 캐기, 돌 이상 도끼로 원목 벗기기 → 나무껍질 섬유, 괭이로 흙 갈기 → 잔디 씨앗, 퇴비통 → 흙)도 도구를 머리로 한 카드로 그리고, 도가니·배럴(가공 탭)의 카드와 함께 그 칸에 있는 아이템의 얻는 법(화살표 오른쪽)·쓰는 곳(왼쪽, 또는 머리의 도구)에 나온다(`codexwork.go`) |
| U(쓰이는 곳) | **쓰는 곳** 보기(상자 칸): 그 아이템이 재료인 레시피를 같은 카드로. 연구 비용·연료·퇴비·장비 재료처럼 그릴 레시피가 없는 것은 기계 머리 줄 아래 한 줄 글 |
| 촉매(만드는 기계) | 카드 묶음의 머리 줄 칸(조합대, 합금로, 정수 추출기, 분쇄기, 화로, 체, 시뮬레이터, 마법 체, 차원 게이트) |
| 즐겨찾기 | 아이템 쪽 머리 줄 오른쪽 끝의 별(네더의 별) 칸: 누르면 그 플레이어의 즐겨찾기에 넣거나 뺀다(세이브에 계정마다 저장, 최대 33개, `codexgoal.go`). 검색 탭 첫 쪽의 최근 본 아이템 위에 나온다 |
| 레시피 사슬의 원재료 | 얻는 법 보기 끝의 "필요한 원재료" 칸(필요 수가 칸에, 가진 수가 툴팁에)(`codexgoal.go`). 원재료를 셀 때는 태그 재료를 대표 아이템으로 세고, 결과물로 다시 만들어지는 되돌리기 레시피(다이아 블록 → 다이아)는 빼며, 재료 대비 결과가 많은 레시피(판자 막대기)를 고른다(`codexRecipeOf`) |
| 재료를 눌러 이동 | 카드의 어느 칸이든 누르면 그 아이템의 도감으로 간다. 지나온 쪽은 브라우저처럼 기록되어 뒤로 버튼이 하나씩 되돌아간다(`codexNav`, 32쪽까지). 탭과 `/도감` 은 기록을 지운다. 연구 화면의 재료·보상 칸에서 들어오면 뒤로 버튼이 연구 화면으로 돌아간다(`codexFrom`) |
| 손에 든 아이템 조회 | `/도감` (아이템을 들고), 메뉴 → 도감 |
| 분류 탭 | 체 탭은 맨 위 블록 줄에서 블록을 고르고 그 아래 모든 메쉬의 드롭 카드, 가공 탭은 맨 위 설비 줄(분쇄기·세척기·전기 화로·합금로·정수 추출기·도가니·참나무 통·돌 통·장비 제작대)에서 설비를 고르면 그 아래 그 설비의 레시피 카드, 몬스터 탭은 시뮬레이터·마법 체 테마·차원 게이트 단계, 식물 탭은 씨앗 → 수확물. 고르는 줄은 가운데에 놓이고, 고른 칸은 금색 테두리(`slot_chosen`)로 그리며, 창 제목에 고른 것의 이름이 붙는다(JEI 의 레시피 분류 이름, `codexPickTitle`) |
| 배치 | JEI 처럼 레시피를 창 가운데에 놓는다. 같은 기계의 카드는 가장 넓은 카드의 폭을 같이 써서 화살표가 한 줄로 서고, 두 장이 한 줄에 들어가면(폭 5칸 이하) 최대 3칸 간격으로 나란히 놓는다. 카드 사이와 맨 위 줄 아래에는 빈 줄을 하나 두고, 기계 머리 줄은 카드의 왼쪽 끝에 맞춘다. 글 줄이 있는 카드는 줄 전체를 쓴다(`codexBlocks`) |
| 스크롤 | 아이템·분류 탭의 레시피 카드는 쪽을 나누지 않고 한 창에 모두 아래로 이어 놓으며, 창에 다 들어가지 않으면 창이 스크롤된다(`codexBoard`) |

## 앞으로의 방향

| 후보 | 내용 | 비고 |
|---|---|---|
| 검색 결과를 상자 창으로 | 결과를 엔티티 상자(`chestui`)의 진짜 아이템 칸으로 보여 주고, 칸을 누르면 도감을 연다. 엔진의 아이템 칸은 폼 버튼보다 가볍고(추정) 이름·설명이 기본 호버 상자로 나온다 | 폼 ↔ 상자 전환 지연이 있다. 같은 목록을 폼과 상자로 열어 프레임·열림 시간을 비교해 정한다 |
