# 다국어(i18n)

서버는 한국어(기본)와 영어를 지원한다. 플레이어마다 클라이언트 언어로 글을 보내고, 카탈로그에 없는 언어는 한국어로 보인다. 다른 언어는 **파일만 더해서** 붙인다. 새 글을 쓸 때 이 문서의 규칙을 따른다.

## 글이 있는 곳

| 종류 | 누가 번역하나 | 어디에 |
|---|---|---|
| 블록·아이템 **이름** | 클라이언트(자기 언어), 서버 글 속 이름은 서버가 플레이어 언어로 | 바닐라 번역 키(`tile.stone.name`, `item.stick.name`), 우리 것은 리소스팩 `texts/ko_KR.lang`·`en_US.lang`(`item.dragonfactory:sieve.name`, `tile.dragonfactory:sieve.name`) |
| 서버가 보내는 **글**(메시지·폼·사이드바·토스트·WAILA 줄·기계 창 아이템) | 서버(`common/i18n`) | `internal/locales/<언어>[.<부분>].json`, common 의 글은 common `i18n/locales/<언어>.json` |
| 리소스팩 UI | 팩 | JSON UI 는 서버가 보낸 글을 그린다. 팩 자체 글(로비 메뉴 이름 등)은 팩의 `texts/*.lang` |
| 숫자·시간 모양 | 서버 | `formatInt`(쉼표), 시간 글은 카탈로그 키(`%d시간 %d분` / `%dh %dm`) |

## 카탈로그 파일

- 한 언어의 글은 여러 파일로 나눌 수 있다. 파일 이름에서 첫 점 앞이 언어다(`en.json`, `en.research.json`, `en.achievements-a.json`, `en.vanilla.json` 은 모두 영어). 키는 파일끼리 겹치지 않게 둔다.
- 영어는 `en.json`(아래 파일 밖의 모든 키), `en.research.json`(`research*`·`advancement.*`), `en.achievements-a.json`·`en.achievements-b.json`(`achievement.*`, 키 순서로 나눔), `en.vanilla.json`(바닐라 이름)이다.
- 새 글은 `ko.json` 에 쓰고 같은 키를 해당 영어 파일에 더한다. `internal/locales/locales_test.go` 가 다른 언어의 키가 한국어에 있는지, 서식 문자(`%d` 등) 수가 같은지 검사한다. 글에 서식 문자가 아닌 `%` 를 쓸 때(`50% 확률`)는 `% c` 처럼 읽히지 않게 쓴다.
- 영어 용어: 연구 Research, 발전과제 Advancement, 업적 Achievement, 칭호 Title, 섬 island, 세이브 save, 체 Sieve, 메쉬 Mesh, 도관 Conduit, 연구 정수 Essence of ~, 몬스터 에센스 ~ Essence, 도감 Codex. 아이템 이름은 팩 `en_US.lang` 과 같게 쓴다.

## 규칙

- **이름은 번역 키로 보낸다.** WAILA 제목은 `Info.NameKey`(`blockNameKey`)를 보내고 클라이언트가 자기 언어로 바꾼다(제목을 raw JSON 으로 보냄, Dragonfly 패치 `SendTitleJSON`). Dragonfly 는 우리 아이템의 `minecraft:display_name` 에 `Name()`(한국어)을 넣으므로, 접속할 때 보내는 아이템 목록(`ItemRegistry`)에서 그 값을 번역 키 `item.<id>.name` 으로 바꾼다(`names.go` `localItemNames`, `dfhook` 서버 패킷 훅). 우리 블록·아이템은 `ko_KR.lang` 과 `en_US.lang` **둘 다**에 이름이 있어야 한다(`pack_test.go` 가 검사). `en_US.lang` 은 클라이언트에서 모든 다른 언어의 대체다. 언어를 더하면 `texts/<코드>.lang` 을 만들고 `languages.json` 에 적는다.
- **서버 글 속 아이템 이름은 플레이어 언어로.** 폼·메시지·사이드바·WAILA 줄에 끼우는 이름은 `itemName(lang, st)`·`tipName(lang, st)`·`blockName(lang, b)` 로 만든다. 우리 아이템·블록은 서버가 시작할 때 팩의 `texts/*.lang` 을 읽어(`LoadNames`) 그 언어의 이름을, 바닐라는 카탈로그의 `vanilla.<id>` 를 쓴다.
- **서버 글은 카탈로그에.** 플레이어에게 가는 글은 `i18n.T(언어, 키, 인자…)` 로 쓴다. 언어는 `i18n.Of(p)`(클라이언트 언어, Dragonfly `Player.Locale()`)다. 화면·패널을 만드는 함수는 `lang` 인자를 받아 아래로 넘긴다(WAILA 줄은 보는 플레이어마다 만든다: `machineLines(lang, m)` 등). 플레이어가 없는 곳(관리 명령 출력, 시작할 때 만드는 데이터)은 `i18n.Default`(한국어)다.
- **표에는 키를 둔다.** 패키지 변수·표(발전과제 `NameKey`·`HintKey`, 기계 종류 `nameKey`·`helpKeys`, 메쉬 `nameKey`, 작물 `cropNameKeys`, 업적 `account.Achievement` 의 `NameKey`·`DescKey`·`TitleKey`·`GroupKey`, 이름 색 `account.Color.NameKey`, 게임 이름 `Game.Name(lang)`)에는 글 대신 카탈로그 키를 두고, 보여 줄 때 `a.Title(lang)` 처럼 바꾼다.
- **창 아이템의 글은 보는 사람마다.** 기계 창의 인벤토리는 연 사람 모두가 함께 보므로 아이템에는 글 하나만 담긴다. 진행 표시·에너지 게이지·정보 아이콘·모두 넣기/꺼내기 버튼·조합법 칸은 이름과 설명을 키와 인자(`wtext`, `windowtext.go`)로 아이템 값에 담고(`withWindowText`), common `chestui.Localize` 가 창 내용 패킷(`InventoryContent`·`InventorySlot`)을 보낼 때 받는 클라이언트의 언어로 다시 쓴다. 아이템 자체의 이름은 한국어다. 기계 창 제목은 여는 플레이어의 언어로 정한다(`openWindow`). 아이템의 커스텀 이름과 설명(lore)에 번역 키를 넣는 방법은 쓸 수 없다: 키 전체(`item.diamond.name`), `%item.diamond.name`, 앞뒤를 감싼 `%item.diamond.name%`(이름이나 설명 한 줄 전체로, 또는 글 중간에) 모두 클라이언트 툴팁에 글자 그대로 보인다(1.26.50 실측).
- **모두가 같이 보는 글은 기본 언어.** 이름표와 채팅 이름 앞의 칭호, 저장되는 아이템의 설명(서랍 아이템, 기간제 아이템의 만료 표시)은 한국어다.
- **조각 이어 붙인 글**("…" + 값 + "…")은 조각마다 키가 하나라, 번역할 때 이어 붙인 결과가 자연스럽게 조각을 맞춘다. 새 글은 `%s` 가 든 한 문장 키로 쓴다.
- 색 코드(`§e`)와 표식(`§0§d§r`)은 번역하지 않는다.
- **코드에 남긴 한국어**: 명령 이름(`/묘목`, `/메뉴발급`, 영어 별칭이 따로 있다), 기간제 아이템에 저장되는 표식 글(`timed.go`).

## 바닐라 이름은 공식 번역에서 (Mojang/bedrock-samples)

바닐라 블록·아이템의 이름은 공식 번역 파일(`bedrock-samples` 의 `resource_pack/texts/en_US.lang`·`ko_KR.lang`)에서 만든다. `go run ./tools/vanillakeys en_US.lang ko_KR.lang internal/games/dragonfactory/vanillakeys.json internal/locales` 가 만드는 것:

- `internal/locales/{ko,en}.vanilla.json`: 모든 바닐라 블록·아이템의 서버 쪽 이름(`vanilla.<id>`, 폼·메시지용).
- `internal/games/dragonfactory/vanillakeys.json`: 클라이언트가 `tile.<id>.name` 으로 못 찾는 블록의 번역 키. 현대 ID 의 이름은 구형 키에 있어(`oak_planks` → `tile.planks.oak.name`, `oak_sapling` → `tile.sapling.oak.name`) 표 없이 보내면 키 글자나 식별자가 보인다. WAILA 의 `blockNameKey` 가 이 표를 쓴다.
- 짝 맞추기: 블록 ID 를 제목 형태로 바꿔("oak_planks" → "Oak Planks") 영어 공식 값에서 찾는다. 못 찾은 것(교육판·테스트 블록·`element_*` 등 약 190개)은 식별자 그대로다.

게임 버전을 올리면 최신 `bedrock-samples` 에서 두 파일을 받아 위 명령을 다시 돌린다.

## 검사

`internal/locales/locales_test.go` 가 ① 코드의 모든 키가 카탈로그에 있는지(`TestKeysInCode`), ② 코드에 한국어가 새로 들어오지 않는지(`TestNoKoreanInCode`), ③ 다른 언어의 키와 서식 문자(`TestCatalogs`)를 검사한다. 키 이름은 자동으로 옮긴 글이 `패키지.파일.함수.번호`(`platform.friends.showFriends.3`), 새 글은 뜻이 드러나는 이름(`분야.대상.부분`)이다. 이름표는 `vanilla.<아이템>`(바닐라), `name.<타입>`(우리 아이템·블록의 서버 쪽 이름, 팩 `ko_KR.lang` 과 같아야 하며 `pack_test.go` 가 검사), 연구는 `research.<id>.*`.

## 남은 일

1. 명령어 설명은 등록할 때 한 번만 정해져 언어별로 못 바꾼다(한국어).
2. 영어 글이 한국어보다 길어 좁은 칸에서 끊기는 곳이 있다(세이브 선택의 "Members" 칸). 팩 레이아웃이나 영어 글을 줄인다.
