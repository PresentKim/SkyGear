# 다국어(i18n) 준비

지금은 한국어만 지원하지만, 다른 언어를 나중에 **파일만 더해서** 붙일 수 있게 글이 어디에 있는지 나누고 틀을 만들어 두었다. 새 글을 쓸 때 이 문서의 규칙을 따른다.

## 글이 있는 곳 네 가지

| 종류 | 누가 번역하나 | 어디에 | 상태 |
|---|---|---|---|
| 블록·아이템 **이름** | 클라이언트(자기 언어) | 바닐라 번역 키(`tile.stone.name`, `item.stick.name`), 우리 것은 리소스팩 `texts/ko_KR.lang`·`en_US.lang`(`item.dragonfactory:sieve.name`, `tile.dragonfactory:sieve.name`) | 팩 파일은 ko/en 둘, WAILA 패널 이름은 번역 키로 보냄 |
| 서버가 보내는 **글**(메시지·폼·사이드바·토스트·명령어 설명) | 서버(`internal/i18n`) | `internal/i18n/locales/<언어>.json` (`ko` 기본, 없는 키는 기본 언어로) | 연구 이름·설명(170개)만 옮김, 나머지는 아래 목록 |
| 리소스팩 UI | 글자 없음 | JSON UI 는 서버가 보낸 글만 그린다(표식·한국어 주석 말고는 글 없음) | 해당 없음 |
| 숫자·시간 모양 | 서버 | `formatInt`(쉼표), 시간 글 | 언어별 모양은 아직 없음 |

## 규칙

- **이름은 번역 키로 보낸다.** 블록·아이템 이름을 서버가 한국어로 적어 보내지 않는다. WAILA 는 `Info.NameKey`(`blockNameKey`)를 쓰고, 클라이언트가 자기 언어로 바꾼다(제목을 raw JSON 으로 보냄, Dragonfly 패치 `SendTitleJSON`). 우리 블록·아이템은 `ko_KR.lang` 과 `en_US.lang` **둘 다**에 이름이 있어야 한다(`pack_test.go` 가 검사). `en_US.lang` 은 모든 다른 언어의 대체다. 언어를 더하면 `texts/<코드>.lang` 을 만들고 `languages.json` 에 적는다.
- **서버 글은 카탈로그에.** 플레이어에게 가는 새 글은 `i18n.T(언어, 키, 인자…)` 로 쓴다. 언어는 `i18n.For(p)`(클라이언트 언어, Dragonfly `Player.Locale()`)이고 `p` 가 없으면 `i18n.Default`("ko"). 키 이름은 `분야.대상.부분`(`research.stick.hint`). 새 글은 먼저 `ko.json` 에 쓰고, 다른 언어 파일에는 있는 만큼만 둔다(없으면 한국어로 보인다). `internal/i18n/i18n_test.go` 가 다른 언어의 키가 기본에 있는지·서식 문자(`%d` 등) 수가 같은지 검사한다.
- 글 안에 아이템 이름을 끼울 때는 서버 한국어 이름표(`names.go` `koreanNames`)를 쓰지 않고 가능하면 번역 키를 쓴다(아래 "남은 일").
- 색 코드(`§e`)와 표식(`§0§d§r`)은 번역하지 않는다. 글 앞뒤에 코드로 붙이고, 카탈로그에는 글만 둔다.

## 바닐라 이름은 공식 번역에서 (Mojang/bedrock-samples)

바닐라 블록·아이템의 이름은 공식 번역 파일(`bedrock-samples` 의 `resource_pack/texts/en_US.lang`·`ko_KR.lang`)에서 만든다. `go run ./tools/vanillakeys en_US.lang ko_KR.lang internal/games/dragonfactory/vanillakeys.json internal/i18n/locales` 가 만드는 것:

- `internal/i18n/locales/{ko,en}.vanilla.json`: 모든 바닐라 블록·아이템의 서버 쪽 이름(`vanilla.<id>`, 폼·메시지용). 손으로 쓴 `ko.json` 위에 합쳐진다.
- `internal/games/dragonfactory/vanillakeys.json`: 클라이언트가 `tile.<id>.name` 으로 못 찾는 블록의 번역 키. 현대 ID 의 이름은 구형 키에 있어(`oak_planks` → `tile.planks.oak.name`, `oak_sapling` → `tile.sapling.oak.name`) 표 없이 보내면 키 글자나 식별자가 보인다. WAILA 의 `blockNameKey` 가 이 표를 쓴다.
- 짝 맞추기: 블록 ID 를 제목 형태로 바꿔("oak_planks" → "Oak Planks") 영어 공식 값에서 찾는다. 못 찾은 것(교육판·테스트 블록·`element_*` 등 약 190개)은 식별자 그대로다.

게임 버전을 올리면 최신 `bedrock-samples` 에서 두 파일을 받아 위 명령을 다시 돌린다.

## 지금 상태 (코드의 한국어 글을 카탈로그로 옮김)

`internal/` 의 Go 코드에서 한국어 글자 상수를 `ko.json` 으로 옮겼다(약 720키). 코드에는 `i18n.T(언어, "키")` 만 남는다. `internal/i18n/i18n_test.go` 가 ① 코드의 모든 키가 카탈로그에 있는지(`TestKeysInCodeExist`), ② 코드에 한국어가 새로 들어오지 않는지(`TestNoKoreanInCode`) 검사한다.

- **키 이름**: 자동으로 옮긴 글은 `패키지.파일.함수.번호`(`platform.friends.showFriends.3`). 새 글은 뜻이 드러나는 이름(`분야.대상.부분`)을 쓴다. 이름표는 `vanilla.<아이템>`(바닐라), `name.<타입>`(우리 아이템·블록의 서버 쪽 이름, 팩 `ko_KR.lang` 과 같아야 하며 `pack_test.go` 가 검사), 연구는 `research.<id>.*`.
- **언어 고르기**: 플레이어가 있는 곳(함수 인자 `p`)은 `i18n.Of(p)` 로 그 플레이어의 언어, 플레이어가 없는 곳(명령 출력, 패키지 변수·표, 시작할 때 만드는 데이터)은 `i18n.Default`(한국어)다. **패키지 변수·표에 든 글(발전과제 이름·힌트, 기계·호퍼·나무 이름, 업그레이드 이름 등)은 시작할 때 한 번 한국어로 정해진다.** 언어별로 바꾸려면 데이터에는 키를 두고 보여 줄 때 `i18n.T(i18n.Of(p), 키)` 로 바꿔야 한다.
- **조각 이어 붙인 글**("…" + 값 + "…")은 조각마다 키가 하나라 어순이 다른 언어에서는 어색하다. 영어를 더할 때 `%s` 가 든 한 문장 키로 합친다.
- **코드에 남긴 한국어**: 명령 이름(`/묘목`, `/메뉴발급`, 영어 별칭이 따로 있다), 기간제 아이템에 저장되는 표식 글(`timed.go`, 저장된 아이템의 글이라 번역하면 못 알아본다).

## 남은 일

1. 영어 번역(`locales/en.json`): 지금은 비어 있어 모두 한국어가 보인다. 없는 키는 한국어로 나오므로 있는 만큼만 채워도 된다.
2. 위 "패키지 변수·표" 글을 플레이어 언어로 보이게 하기(데이터에 키를 두고 보일 때 번역).
3. 사이드바는 지금 섬 전체가 같은 글을 보므로 플레이어별로 만들어야 한다.
4. 명령어 설명은 등록할 때 한 번만 정해져 언어별로 못 바꾼다.
5. WAILA 패널의 줄과 아이템 줄 이름(부제목이라 번역 키를 못 씀 — 부제목도 JSON 으로 보내는 방법을 검토).
6. 폼·메시지의 아이템 이름은 서버 이름표(`vanilla.*`)를 쓴다. 클라이언트 번역으로 바꾸려면 폼 글에 번역 키(`%tile.x.name`)가 먹히는지 실기로 확인해야 한다.
7. 시간·숫자 모양(`formatInt`, "n시간 m분")은 언어별 모양이 필요해지면 카탈로그로.
