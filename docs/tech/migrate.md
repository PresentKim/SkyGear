# 저장 데이터 패치

릴리스가 바뀌어 블록·아이템 이름이나 저장 형식이 달라져도 세이브가 그대로 열리도록, 서버는 시작할 때 저장 데이터를 새 형식으로 고쳐 쓴다. 코드는 `content/skygear/migrate`이고, 호출은 `cmd/skygear/main.go`가 DB 스키마를 올린 뒤, 월드를 열기 전에 한다(`migrate.Run`).

## 버전 기록과 실행

- 세이브는 자기 데이터가 어느 릴리스(`연.월.빌드`)의 형식인지 `save_state` 의 `skygear.version` 키(`migrate.VersionKey`)에 적는다. 세이브 밖 데이터(계정, 업적, 카운터)는 `data_versions` 표의 `accounts` 범위에 적는다([기획 03 §2](../design/03-architecture.md)).
- `Run`은 기록이 어떤 패치의 `Version`보다 오래된 범위만 고친다. 패치는 오래된 것부터 차례로 적용하고, 끝나면 실행 중인 릴리스(`Stamp`)를 기록한다. 릴리스 사이에 만든 빌드는 가장 새 패치의 버전을 기록한다.
- 고치기 전에 백업 폴더(`platform.toml` 의 `Backup.Dir`)에 사본을 만든다: DB는 `migrate-db-<날짜-시각>.sqlite`, 세이브 월드는 `migrate-save<세이브 ID>-<날짜-시각>.tar.gz`다. 월드 사본은 세이브마다 최근 3개를 둔다.

## 패치

`patches.go`의 `Patches` 끝에 새 패치를 더한다. 릴리스에 들어간 패치는 고치지 않는다. 패치 하나(`Patch`)는 다음을 가진다.

| 필드 | 하는 일 |
|---|---|
| `Version`, `Name` | 이 변경이 들어가는 릴리스와 이름 |
| `Rename` | 문자열을 새 값으로 바꾼다. 키와 같은 문자열, 또는 키 뒤에 `:` 와 아이템 메타가 붙은 문자열이 대상이다 |
| `Plain` | `Rename`과 같되, 이 이름의 아이템 묶음을 이름·설명·값·내구도·아이템 NBT가 없는 새 아이템의 평범한 묶음(개수는 그대로)으로 만든다. 인벤토리, 상자, 아이템 엔티티, 분실물처럼 묶음이 저장되는 곳 어디서나 한다. 한 이름은 `Rename`과 `Plain` 중 하나에만 둔다 |
| `Blocks` | 서브청크 팔레트의 블록을 이름과 블록 상태째로 바꾼다. 다른 블록으로 바뀌는 블록은 상태가 필요하다(없으면 처음 등록된 상태가 된다) |
| `Block.DropEntities` | 바뀌기 전 블록의 블록 엔티티를 새 블록이 쓰지 않을 때 켠다. 바뀐 블록 자리의 블록 엔티티를 월드에서 지운다(`dropentities.go`) |

## 고치는 곳

- 월드(mcdb): 서브청크 팔레트의 블록 이름, 블록 엔티티·엔티티·아이템의 NBT(`common/nbtrewrite`). 바뀐 이름이 들어 있지 않은 값은 건드리지 않고, 읽을 수 없는 값은 그대로 두고 경고를 남긴다.
- DB: 세이브 범위는 `save_id` 열이 있는 표의 그 세이브 행, 계정 범위는 `save_id` 열이 없는 표의 문자열·BLOB 열이다. JSON 속의 아이템 NBT(분실물)와 텍스트도 바꾼다.
- 스토리지 망 디스크: 세이브 상태 문서의 `net_disks`(디스크 ID → 아이템 키 → 개수)는 키를 다시 쓴다(`diskkeys.go`). 키는 아이템 NBT를 정규형(`common/nbtcanon`)으로 쓴 것의 base64이므로, 이름이 바뀐 아이템은 키도 바뀐다.
  - 새 키는 실행 중인 서버가 만드는 키(`netstore.KeyOf`)여야 하므로 `netstore`가 `migrate.ItemKey`를 채운다(`migratekeys.go`). 비어 있으면 고친 NBT의 정규형을 키로 쓴다.
  - 키가 하나로 합쳐지면 개수를 더한다. 디스크의 총 개수는 변하지 않는다. 읽을 수 없는 디스크나 개수가 넘치는 디스크는 그대로 둔다.
  - `nbtcanon`은 키를 만드는 쪽(`netstore`)과 고치는 쪽(`migrate`)이 함께 쓰는 하나의 코덱이다.
