# WAILA 도입 검토

대상: WAILA v5.1.1 (r4isen1920, **MIT 라이선스**, `.mcaddon` = 리소스팩 + 행동팩). 바라보는 블록·엔티티의 이름·아이콘·정보를 화면 위에 띄운다.
**1~3단계 도입함**(아래 "구현"). 원 애드온 분석은 그 아래.

## 구현

- 제목 접두어·토큰은 원본의 `_r4ui:`(제작자 이름에서 온 것) 대신 `_waila:` 를 쓴다(11차 실기 뒤). 한 글자 길어서 팩의 제목 위치 자르기(`'%.Ns' * $var_title_text`)를 모두 1씩 늘렸다. 아래 "구조" 이후는 원본 분석이라 `_r4ui:` 그대로 둔다.
- 리소스팩: `assets/resourcepack/waila/`(원본 + `README.md` 의 변경점: 새 UUID·행동팩 의존 제거, `hud_screen.json` 네임스페이스, 아이콘을 부제목에서 읽는 `df_subtitle_item_renderer`).
- `internal/waila`: 제목 형식(`Format`), 보내기(`Show` — 바뀐 것만, 30초마다 다시; `Clear`), 도구 아이콘(`ToolsFor`: Dragonfly `BreakInfo` 로 효과 있는 도구와 최소 등급, 손에 든 것이 맞으면 `a`·필요한데 틀리면 `b`). 우리 블록은 어떤 도구로도 빨라지지 않아(`customBlockEffective`) 판정에 안 걸리므로 `look.go` `customTool` 이 어울리는 도구를 보인다(서랍·납품함 도끼, 기계·코어 곡괭이, 들고 있으면 ✓; 11차 실기).
  - 제목: `_waila:A:` + 도구 칸 10자(`aa,a;zz,z:`) + `§f이름` + `\n§7정보 줄…` + `__waila:anchor.top_middle__`. 출처 줄(드래곤팩토리/Minecraft)은 쓰지 않는다(11차 실기).
  - 부제목: `i` + 아이콘 칸 11자(아이템 런타임 ID × 65536 을 왼쪽에 `x` 로 채움, 빈 것은 `xxxxxxxxxx0`) + (보관 블록이면 칸들) + `e`. 숫자만 보내면 팩이 부제목을 문자열로 다루는 블록 상태 검사가 깨져 회색 칸과 "expected a string" 경고가 났다(11차 실기).
  - 팩이 칸을 꺼내는 법: 제목 팩토리가 주는 **변수** `$var_subtitle_text`(패널 글자도 모두 이 변수로 그린다)에서 `'%.11s'` 로 칸을 잘라 `x` 를 지우고, `property_bag` 의 `#item_id_aux` 에 넣는다. 원본 WAILA 옛 버전이 제목에서 아이템 값을 읽던 방식(`item_aux_renderer`, `':-00000NaN'` 검사 흔적)이다. 11차 실기에서 아이콘·칸이 보이는 것을 확인했다(서랍·상자·화로·통).
    - 실패한 방식(11차 실기 진단): **바인딩** 식(`#hud_subtitle_text_string`)으로 칸을 꺼내기 — `'%.Ns'` 로 자른 값, 0으로 채운 고정 폭, 1610612736 더하고 빼기, `x` 채우고 지우기, 앞뒤를 지워 남기기 모두 아이콘이 비었다. 음수·양수 차이는 없었다(통·서랍 둘 다 실패).
    - 진단에서 본 성질: 숫자로 바뀐 값은 글자(label)에 표시되지 않는다(칸 수량 `" 219"` 도 그래서 안 보였다; 변수 식 안에서 `'§r' + 값` 으로 문자열로 만든다 — 라벨 text 에서 `('§r' + $변수)` 로 이으면 변수의 식이 계산되지 않고 글자 그대로 붙었고, 부모 패널 변수 블록에 둔 식도 글자에 나오지 않아 개수 식은 라벨 자신의 변수 블록에 둔다). 바인딩 식은 `#바인딩` 을 하나도 안 쓰면 "Must define a source property name" 오류.
    - 블록 상태 칸(`main.r4ui` `block_states`)은 쓰지 않아 끄고, 그 "expected a string" 경고도 없앤다.
  - 이름 줄 최소 높이는 10(원본 20은 아이콘 높이라 칸·줄이 아이콘 아래로 내려갔다, 11차 실기).
  - 위치: 위 가운데, 보스바(긴급 매입) 아래로 26 내림(`main.r4ui`). Dragonfly 패치로 부제목을 제목보다 먼저 보낸다.
  - 일반 제목(레벨 업·긴급 매입)은 `waila.SendTitle` 로 보내고, 그 제목이 끝날 때까지 패널을 멈춘다.
- 드래곤팩토리(`look.go`): 움직이거나 돌 때(0.1초에 한 번까지)와 0.2초마다(`instance.FastTicker`; 매초로는 게이지가 끊겨 보였다, 11차 실기), 눈에서 6블록까지 광선 검사(공기·액체는 제외). 작물은 단계에 따라 높이가 자라는 상자(단계+1)/8 로 판정한다: 낮은 작물 위 빈 곳을 지나는 시선은 뒤 블록을 본다(클라이언트와 같게, 11차 실기). 충돌 상자 없는 다른 블록(꽃 등)은 칸 전체. 섬 확장 모드에서는 끈다.
  - 정보 줄: 기계(아이템 줄 "흙 [아이콘] ×3 ◔": 넣은 아이템·개수·진행 게이지, 비면 회색 "비어있음", 결과 칸에 든 것은 "결과" 줄, 칸 표시는 없음 — 11차 실기; 진행·채굴·판매·수확 주기는 원형 게이지 글리프로: `glyph_E1` 둘째 줄 U+E110~E11A 에 `cycle_0..10` 텍스처를 10px(칸의 약 60%)로 줄여, 11차 실기), 서랍(아이콘은 서랍 블록, 줄은 "참나무 원목 [작은 아이템 아이콘]" — 수량·잠금·업그레이드는 서랍 앞면에 보이므로 패널에서 뺀다, 비면 회색 "비어있음" — 11차 실기; 이름 옆 작은 표시 `df_marks` 는 지금 쓰는 블록이 없다), 코어(아이템 줄 "생성물: 조약돌 [아이콘] ◔", 위 칸 막힘, 코어 기반이 아니면 "코어 기반: 참나무 원목 또는 조약돌" — 11차·13차 뒤), 작물("남은 시간"·"다음 열매"만, 단계 숫자는 쓰지 않는다 — 11차 실기), 납품함(미션).
- **부제목 꼬리**(`internal/waila/tail.go`): 칸 18개 뒤에 줄 아이콘 칸(11자), 표시 4자(`L`/`-`, 용량 업그레이드 `a`+단계, `V`/`-`, 줄 게이지 `a`+10분의 몇 또는 `-`; 숫자 한 글자는 팩에서 숫자가 되어 글자 비교가 맞지 않아 ×2 가 안 보였다 — 글자를 쓴다), 줄 글자 24바이트(`~` 로 채움, 숫자처럼 보이면 안 보이므로 `§f` 로 시작), 그리고 나머지가 줄 이름(한글은 여기만: 팩이 위치로 자르므로 앞쪽은 모두 ASCII). 팩은 `tile.r4ui` `df_marks`(이름 옆, `main.r4ui` `df_name_row`)와 `df_item_line`(제목에 `__waila:df.line__` 이 있을 때). 표시 글자는 변수 블록에 식이 아닌 고정 글자로 고른다(변수 블록의 식을 다른 식 안에 쓰면 계산되지 않는다).
- 확인: `waila_test.go`, `look_test.go`, 시나리오 `spike/scenarios/waila.sh`(`/dfadmin look 0 90` 으로 바닥을 보면 `_waila:A:` 제목이 옴).
- 작물 우클릭 시간 글자는 없앴다(패널이 대신, 11차 실기 뒤).
- **보관 블록 내용**(칸 회색 테두리는 지움, 11차 실기): 상자·통·셜커 상자(묶어 세기, 한 줄 9종류까지, 나머지는 생략 — 11차 실기), 자동 자원 채굴기(결과 1칸, 11차 실기), 화로류(입력·연료·결과, 화살표 자리에 진행도 화살표 아이템 `progress_0..10` — 불이 꺼져 있으면 빈 화살표, 패널 칸 17, 11차 실기), 호퍼, 양조대. 제목에 `__waila:inv.<chest|furnace|hopper|brewstand>__`을 붙이고,
  부제목 아이콘 칸 뒤에 패널 칸 18개(8번은 아이콘 자리로 비움)마다 아이템 11바이트(아이콘과 같은 형식) + 수량 8바이트(`§f74` 처럼 색 코드로 시작해 `~` 로 채움, 1개면 `~` 만, 1만부터 `k`)를 붙인다. `'%.Ns'` 는 바이트로 자른다.
  원본은 플레이어 인벤토리 9~35칸에 실제 아이템을 잠깐 넣었지만, 우리는 `tile.r4ui` `item_inventory` 를 부제목에서 읽게 고쳤다(바인딩 식에 변수를 못 써서 칸 번호마다 고정 식을 변수로 골라 끼움, 생성).

## 구조

| 팩 | 내용 | 크기 |
|---|---|---|
| 리소스팩 | `ui/hud_screen.json`(HUD 수정), `ui/r4isen1920/waila/*.r4ui`(JSON UI 본체: main·tile·entity·common, 약 80KB), 아이콘·태그 텍스처, 29개 언어(`ko_KR.lang` 포함) | 약 200KB |
| 행동팩 | **Script API** (`@minecraft/server` 2.4.0, `server-ui` 2.0.0) `scripts/main.js` 한 파일(약 120KB, 번들), 설정 폼 | 약 120KB |

- 최소 엔진 1.21.100.
- **Dragonfly 는 Script API(JavaScript 행동팩)를 실행하지 않는다.** 리소스팩만 그대로 쓸 수 있고, 행동팩이 하던 일은 Go 로 다시 만들어야 한다.

## 동작 방식

1. **매 틱 바라보는 대상 찾기**: `getBlockFromViewDirection` / `getEntitiesFromViewDirection`(최대 거리 설정값, 물속이면 액체 제외).
2. **제목(title) 문자열로 HUD 에 데이터 전달**: `onScreenDisplay.setTitle(제목, {부제목, 페이드 0, 표시 시간})`.
   - 제목은 `_r4ui:A:`(블록·아이템 액자 등) 또는 `_r4ui:B:`(엔티티)로 시작하고, 그 뒤에 고정 순서의 필드가 붙는다:
     체력·방어 렌더러 문자열, 도구 아이콘(`zz,z;zz,z:` 형식), 상태 효과(`…eNN`), 이름(번역 키), 체력 수치 줄, 줄바꿈 여백, `§9§o` + 애드온(네임스페이스) 이름,
     `__r4ui:inv.size_NN__`, `__r4ui:anchor.<위치>__`, `__r4ui:inv.chest__` 같은 토큰.
   - 부제목에는 블록 상태(`__r4ui:block_states__` 뒤)를 넣는다(웅크리면 자세히).
   - `hud_screen.json` 은 제목이 `_r4ui:` 로 시작하면 바닐라 제목 대신 WAILA 패널을 그리고, 아니면 바닐라 제목을 그대로 보인다(`'%.6s' * #text = '_r4ui:'`).
3. **아이콘은 "인벤토리 미러" 꼼수**: 바라보는 블록의 아이템을 플레이어 인벤토리 17번 칸(상자 내용은 9~35번)에 **실제로 잠깐 넣고**, HUD 가 `inventory_items` 컬렉션의 `#item_id_aux` 를 `binding_condition: visibility_changed` 로 한 번 읽은 뒤 2틱 뒤에 원래 아이템을 되돌린다(백업은 플레이어 동적 속성).
4. 설정은 `server-ui` 폼(표시 위치, 웅크릴 때 자세히, 애드온 이름 표시 등), 플레이어별 저장.

## 우리 서버에 들일 때

### 그대로 못 쓰는 것
- 행동팩 전체(스크립트). → 서버(Go)가 대신: 시선 추적, 제목 문자열 만들기, 보내기.
- **인벤토리 미러는 쓰면 안 된다.** 서버가 인벤토리를 실제로 바꾸면 접속 끊김·저장 시점과 겹칠 때 아이템 복사·손실 위험이 있고, 우리 인벤토리 로직(chestui, 서랍, 기간제)과 부딪친다.
  대신 (a) 그 플레이어에게만 가짜 칸 패킷(`InventorySlot`)을 보내 HUD 가 읽게 하고 곧 진짜 칸을 다시 보내거나(서버 인벤토리는 그대로), (b) 제목에 아이템 런타임 ID × 65536 을 넣고 `tile.r4ui` 를 고쳐 `#item_id_aux` 를 제목에서 바로 읽는다(폼 아이템 아이콘과 같은 방식, `json-ui.md`). (b)가 깔끔하다.

### Go 로 할 일
- 플레이어마다 2~4틱에 한 번 눈 위치에서 시선 방향으로 블록·엔티티 광선 검사(최대 5~6블록), **대상이 바뀔 때만** 제목을 보낸다(대역폭). 대상이 없으면 제목 지우기.
- WAILA 제목 형식 만들기: 처음에는 블록(`A`)만. 이름은 한글 이름(`names.go`), 애드온 이름 줄은 "드래곤팩토리"/"Minecraft", 도구 아이콘은 Dragonfly `BreakInfo`(효과 있는 도구·채굴 가능)로.
- **우리 정보 줄 추가**(가장 큰 이득): 기계 진행도·대기, 서랍 아이템·수량·잠금, 작물 남은 시간, 코어가 만드는 것·다음 생산, 납품함 미션. 지금의 작물 우클릭 글자나 예전 기계 위 글자를 대신할 수 있다.
- 제목 충돌: 레벨 업·긴급 매입은 바닐라 제목을 쓴다. 제목은 한 번에 하나라 WAILA 갱신이 그것을 덮으므로, 일반 제목을 보낸 뒤 몇 초는 WAILA 를 멈춘다.
- 설정(켜기·끄기, 위치)은 우리 폼으로.

### 리소스팩
- WAILA 리소스팩을 `assets/resourcepack/waila/` 로 넣는다(MIT: `LICENSE` 유지, 출처 표기). `hud_screen.json` 은 우리 팩이 아직 건드리지 않아 충돌 없다.
- 도입 뒤 고칠 것: 아이콘을 (b) 방식으로, 우리 테마 색, 필요 없는 엔티티 부분은 그대로 두되 서버가 보내지 않으면 안 쓰인다.

## 단계 제안
1. 리소스팩만 넣고, 서버가 고정 문자열 제목(`_r4ui:A:…`)을 보내 실기에서 패널이 뜨는지 확인(형식 검증).
2. 블록 대상: 광선 검사 + 이름·애드온 줄·도구 아이콘 + 아이콘((b) 방식).
3. 우리 블록 정보 줄(기계·서랍·작물·코어).
4. 엔티티(요정·플레이어 등)는 필요할 때.
