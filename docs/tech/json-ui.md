# JSON UI (드래곤팩토리 테마)

폼과 기계 창의 모양은 리소스팩 JSON UI 로 바꾼다. 서버는 폼 내용만 보내고, 모양은 클라이언트가 팩으로 그린다.
폼·HUD 테마는 게임과 상관없어 `common/packs/dfui` 에 있고, 기계 창·로비 틀처럼 이 게임에만 있는 것은 `dragonfactory` 팩에 있다. `main.go` 가 `dragonfactory` 를 `dfui` 보다 먼저(스택 위에) 싣는다.

레이아웃 13개(목록·카드·상점·표·칸·분할·트리·런처 등)는 `server_form.json` 의 `long_form` 아래에 모두 있고 제목 표식으로 `visible` 만 바뀐다. 그래서 어느 폼을 열든 모든 레이아웃이 만들어지고 배치된다. 맞는 레이아웃 하나만 팩토리로 만드는 게이트(`property_bag` 의 역할 이름 배열을 `('#이름_' + 조건)` 으로 골라 `#collection_length` 에 주는 방식)는 동작하지만, 우리 팩토리가 만든 컨트롤 안에서는 `#form_button_contents` 로 버튼을 만드는 팩토리와 고정 `collection_index` 칸이 비어(격자만 채워진다) 지금 레이아웃에는 쓸 수 없다. 쓰려면 레이아웃이 버튼을 격자로만 읽게 바꿔야 한다.

## 파일

| 파일 | 내용 |
|---|---|
| `common/packs/dfui/ui/server_form.json` | 바닐라 `server_form.main_screen_content`(전체 화면으로)·`long_form`·`custom_form` 을 덮어써 모든 서버 폼을 어두운 테마로. 제목 앞 표식으로 분기: `§d§f§c§r`(`ui.CardToken`) 카드 격자, `§d§f§s§r`(`ui.ShopToken`) 촘촘한 상점 격자, `§d§f§t§r`(`ui.TableToken`) 표, `§d§f§i§r`(`ui.SlotToken`) 인벤토리처럼 보이는 칸(보이기만 하는 보관 칸 `§0§9§r`과 옆 글 `§0§b§r`, 누르는 왼쪽 칸 `§0§a§r`·오른쪽 칸 `§0§c§r`, 서랍 창; 칸 글자가 안내 문구 — 마우스는 hover·pressed 상태에 안내 상자. 터치(`$touch`)는 서랍 창(`slot_*`)만 바닐라 라디오 토글로 첫 탭 선택·안내, 선택된 칸 위에만 진짜 버튼이 있어 다시 탭하면 실행). 폼은 누른 버튼을 글자로 찾으므로 같은 글자의 버튼은 `ui.Menu` 가 `§r` 을 붙여 구별한다, 없으면 목록 |
| `common/packs/dfui/ui/df_form.json` | 테마 컨트롤(`df_form` 네임스페이스): 창(패널·제목 막대·닫기), 목록 버튼(아이콘+글자), 카드 격자, 입력 폼. 글자는 팩 번역 키(`dfui.*`, `texts/*.lang`) |
| `common/packs/dfui/ui/dfui_hooks.json` | 테마가 그리지만 서버 팩이 채우는 자리(`dfui_hooks` 네임스페이스): `lobby_frame`(로비 틀, 테마에서는 비어 있다)과 그것을 폼 배경에 표식으로 띄우는 `form_frame`. 서버 팩은 같은 경로의 파일에서 같은 이름을 다시 정의한다 |
| `assets/resourcepack/dragonfactory/ui/dfui_hooks.json` | `dfui_hooks.lobby_frame` 을 `df_lobby.frame` 으로 채운다 |
| `assets/resourcepack/dragonfactory/ui/df_machine.json` | 기계 창 레이아웃(`df_machine`): 바닐라 작은 상자 화면에서 그 기계의 칸만 정해진 위치에 |
| `common/packs/inventoryui/ui/chest_screen.json` | 제목 표식 `§d§m§1`~`§d§m§5` 이면 기계 창으로 분기(PC 화면만, 모바일은 크기 지정 상자 그대로) |
| `common/packs/dfui/textures/ui/df/*` | 테마 텍스처. `common/` 에서 `go run ./tools/uitextures` 로 다시 만든다(색은 그 파일 위쪽). 서랍 업그레이드 빈 칸(`slot_empty_*`)만 `dragonfactory` 팩에 있다 |

## 폼 (메뉴·확인·입력)

- 항목을 넣고 빼지 않는 메뉴는 **폼**으로 만든다(상자 아님): 드래곤팩토리 메뉴, 분실물 보관함, 섬 확장 지도 등.
- 카드 격자 폼(`ui.CardMenu`): 아이콘 위·글자 아래 카드가 한 줄에 3개(90×50 칸, 격자 폭 270px 고정·가운데, 창 296px), 버튼 수만큼 줄이 늘어난다(스크롤). 드래곤팩토리 메뉴·도움말·로비 메뉴·이름 색. 더 작은 칸이 많을 때는 촘촘한 격자(`ui.ShopMenu`).
  - 격자 항목 수는 본문 앞 12바이트에서 읽는다: `ui.Menu` 가 격자 칸 수를 `§r§r§r` 과 세 자리 숫자(`§r§r§r042`)로 본문 맨 앞에 쓰고, 팩이 `((('%.12s' * #form_text) - '§r') - 0)` 으로 숫자를 꺼내 `#maximum_grid_items` 로 묶으며 본문 글에서는 이 12바이트를 뺀다. 클라이언트의 `#form_button_length` 는 지금까지 보인 가장 큰 폼의 버튼 수로 남아 쓰지 않는다. 숫자를 앞에 두면 잘라낸 12바이트가 통째로 숫자로 읽혀 본문 자르기 식이 깨지므로 `§r` 을 앞에 둔다(식 결과 문자열은 생김새로 타입이 다시 정해진다). 펼치는 격자(`ui.ItemGrid`·`ui.ItemBoard`)는 칸 버튼 수만 보내, 뒤에 오는 탭·뒤로·쪽 버튼이 빈 줄을 만들지 않는다.
  - 격자 높이는 `100%c` 로 묶는다(`#form_button_contents` 나 `default` 높이면 버튼이 하나도 안 생긴다).
- 목록 폼(`ui.Menu`): 버튼마다 아이콘(`ui.Option.Icon`) + 글자. 아이콘은 두 가지:
  - `textures/...` 로 시작하는 텍스처 경로: 이미지로 그린다(메뉴 항목 등 아이템이 아닌 것).
  - **아이템**: `ui.ItemIcon`(`dragonfactory.iconOf`)이 아이템 런타임 ID × 65536 을 숫자 문자열로 넣는다. 테마의 `button_icon_item`(`inventory_item_renderer`)이
    그 값을 `(#form_button_texture - 0)` 으로 숫자로 바꿔 `#item_id_aux` 로 받아 인벤토리 칸처럼 아이템을 직접 그린다(식에는 `%` 연산자가 없다). 블록은 블록 모양 그대로, 아이콘 텍스처 경로를 따로 관리할 필요가 없다(빠진 경로 때문에 아이콘이 안 보이던 문제 해결).
    패키지 변수 초기화 때 만들면 안 된다: 아이템 등록(`init`) 전이라 런타임 ID 가 없어 빈 아이콘이 된다. 폼을 만들 때 계산한다.
    방식은 Chest-UI 와 같고, `#item_id_aux` = ID × 65536 + 데이터값은 바닐라 `inventory_screen.json`·bedrock-wiki 표와 같다. 데이터값(메타)은 쓰지 않는다.
- 확인 폼(`ui.Confirm`)은 바닐라 modal 이 테마를 받지 않아(8차 실기: 밝은 기본 창) **목록 폼 두 버튼**(확인·취소)으로 보낸다. 닫기는 취소와 같다.
- 수량 폼(`ui.Amount`): 입력 폼(custom_form)의 슬라이더 하나.
- 입력 폼은 제목 막대와 스크롤을 끈다(`$df_title: false`, `custom_form_content` 가 바닐라 `custom_form_scrolling_content` 대신 필드와 제출 버튼만 쌓는다). 필드 그룹 라벨이 곧 질문이다. 제출 버튼 글은 테마 팩 `texts/*.lang` 의 `dfui.submit`("확인"), 제목에 `ui.CreateToken` 이 있으면 `dfui.create`("생성하기").
- 세이브 생성 입력은 `ui.CreateToken`(`§d§f§e§r`)을 제목 앞에 붙여 창을 만든다.

### 버튼 표식 (탭·뒤로·표)

버튼 글자 앞의 표식(유효한 색 코드라 테마가 없어도 글자에 안 보임)으로 버튼의 자리를 정한다. 표식은 모두 `§0§` 로 시작하고, 목록·격자는 표식 있는 버튼을 숨긴다. 표식 버튼은 일반 버튼 **뒤에** 둔다(격자에서 숨긴 칸이 끝에만 생기게).

| 표식 | Go | 자리 |
|---|---|---|
| `§0§1§r` / `§0§2§r` | `ui.Tab(…, selected)` | 창 위쪽 탭 줄(선택된 탭은 밝게) |
| `§0§3§r` | `ui.Back` | 제목 막대의 닫기 버튼 왼쪽 작은 화살표 버튼 |
| `§0§4§r` | 표의 동작 버튼 | 표 아래 목록 버튼 |
| `§0§5§r`·`§0§6§r` | `ui.Cell` | 표의 칸(글자·숫자, 머리 칸은 회색 글자), 버튼이 아니라 눌리지 않음 |
| `§0§8§r` | 표의 합계 | 표 아래 오른쪽 어두운 글자 |

- 탭 줄·뒤로 칸·합계·동작은 `df_form.marked_buttons`: 모든 버튼을 도는 가로/세로 스택 팩토리에서 그 표식 버튼만 보이게 한다(숨긴 컨트롤은 스택에서 자리를 차지하지 않음).
- 표(`ui.TableMenu`)는 4열(76px) 격자. 첫 열은 아이콘+이름, 숫자 열은 오른쪽 정렬이다.
- 상점(`ui.ShopMenu`)은 318px 창, 50×46px 칸 6열의 인벤토리 같은 작은 카드(아이콘·이름·가격). 격자 폭(300px)이 내용 영역을 넘으면 왼쪽 열이 잘린다.
- 탭 줄 높이는 `100%cm`(가장 큰 자식). 가로 스택의 `100%c` 는 자식 높이를 모두 더해 탭 아래에 큰 공백이 생겼다.
- 입력 폼(custom_form): 어두운 창 안에 바닐라 입력 칸 그대로(밝은 카드 위에서는 입력 글자가 안 보인다).
- 폼 뒤를 어둡게 하는 배경은 두지 않는다(화면 일부에만 그려진다).

### 아이템 슬롯 폼 (연구, 분실물)

폼 버튼으로 **인벤토리 칸 같은 경험**을 준다: 칸마다 아이템 그림, 오른쪽 아래에 작은 개수, 마우스를 올리면(터치는 누르고 있는 동안) 이름·설명 상자. (서랍 창 `ui.SlotMenu` 의 칸을 일반화한 것.) 칸·개수·호버는 실기에서 확인했다. 호버 상자는 아래처럼 엔진 툴팁으로 그려 폼 밖으로 잘리지 않는다.

| Go | 제목 표식 | 쓰는 곳 |
|---|---|---|
| `ui.ItemDetail(p, title, ui.Detail, rows, actions...)` | `§d§f§g§r` | 상세 창(326px 2단): 왼쪽 카드(큰 아이템 + 이름·상태 글자 + 그 아래 동작 버튼) 아래에 설명(폼 본문), 오른쪽 위·아래에 제목 있는 칸 줄 2개("필요한 재료", "보상 레시피", 한 줄 8칸, 넘으면 9번째부터 둘째 줄: 버튼 글 11번째 바이트가 `2`) |
| `ui.ColumnsMenu(p, title, body, left, right, actions...)` | `§d§f§j§r` | 도관 면 설정(326px): 위에 본문 판, 아래에 나란한 두 판(왼쪽·오른쪽), 각각 제목과 칸 한 줄. 판마다 전용 표식(왼쪽 `§0§k§r` 칸·`§0§l§r` 작은 버튼, 오른쪽 `§0§m§r`·`§0§n§r`)을 쓰고, `ItemSlot.Mini` 칸은 틀 없는 작은 버튼으로 앞 칸 옆에 붙는다. 호버 상자는 왼쪽 판은 오른쪽으로, 오른쪽 판은 왼쪽으로 |
| `ui.ItemGrid(p, title, body, slots, actions...)` | `§d§f§h§r` | 분실물 보관함, 스토리지 목록 등: 18px 칸이 줄바꿈하며(한 줄 11칸, 창 224px) 세로로 스크롤. 탭·동작 버튼은 칸보다 앞에 보낸다 |

- `ui.ItemSlot{Icon, Count, Tip, Run}`: `Icon` 은 `ui.ItemIcon`(아이템 그림), `Count` 는 오른쪽 아래 글자(색 코드로 시작, 10바이트까지; `ui.CountText` 가 1만부터 `12k`), `Tip` 은 호버 상자 글(여러 줄 가능), `Run` 은 누르면 할 일. **칸을 누르면 폼이 답해 닫히므로 `Run` 은 폼을 다시 띄워야 한다.**
- **버튼 글자에 값을 고정 위치로 싣는다**(WAILA 보관 블록 칸과 같은 방식): 표식 9바이트(`§0§d§r` 줄 A, `§0§e§r` 줄 B, `§0§f§r` 줄바꿈 격자) + **호버 상자 쪽 1바이트**(`l`/`r`) + 개수 10바이트(`~` 로 채움) + 나머지는 호버 글. 팩은 `'%.9s'`, `'%.10s'`, `'%.20s'` 로 자르고 빼서(`df_form.json` `gslot_count`·`gslot_tooltip_text`) 개수의 `~` 를 지운다. 개수가 색 코드로 시작해야 하는 이유: 숫자만 있는 글은 숫자로 바뀌어 라벨에 안 나온다.
| `ui.ItemGridSections(p, title, body, sections, actions...)` | `§d§f§h§r` | 연구 목록: 제목이 있는 구역(`ui.GridSection`)이 한 격자 안에 차례로 놓인다. 구역마다 제목 칸(`§0§g§r`, 글이 오른쪽 빈 칸 위로 이어짐) + 빈 칸 10개(`§0§q§r`)로 한 줄을 차지하고, 슬롯 뒤에도 빈 칸을 채워 줄을 맞춘다(줄바꿈은 Go 가 정한다). 칸 번호: 첫 구역의 첫 슬롯이 11번 |
| `ui.SplitMenu(p, title, ui.Split{…})` | `§d§f§y§r` | 연구 화면: 창 위 탭, 왼쪽 칸 격자(8×7: 연구 48칸과 맨 아래 줄 양 끝의 쪽 화살표), 오른쪽 고른 항목의 상세([research-screen.md](research-screen.md)) |
| `ui.ListSplitMenu(p, title, ui.ListSplit{…})` | `§d§f§l§r` | 세이브 선택·친구·멀티 플레이·참여자 관리(326×126): 창 위 탭(`ui.Tab`, 친구 화면), 왼쪽 줄 목록(창 높이로 고정, 길면 스크롤), 오른쪽 본문과 동작 버튼(버튼이 필요한 높이만 차지). 줄 표식 `§0§o§r`, 고른 줄 `§0§x§r`. 줄 글은 `ui.ListRowText(이름, 정보)` 로 이름 60바이트(보이지 않는 `§r` 패딩) 뒤에 정보 줄 — 테마가 앞 60바이트를 이름, 나머지를 작은 회색 정보 줄로 나눠 그린다. 동작은 첫 버튼이 전체 폭, 나머지는 두 칸씩(`§0§0§r` 전체 폭, `§0§y§r`·`§0§z§r` 왼쪽·오른쪽 칸). 2열은 `panel`(높이 `100%cm`) 안에 왼쪽·오른쪽으로 붙인 두 세로 스택이다(가로 스택에서는 높이가 0 이 됐다) |
| `ui.Help(tip, run)` | 제목줄 | 뒤로가기 왼쪽의 "?" 버튼(`§0§p§r`): 마우스를 올리면 엔진 툴팁으로 `tip`, 누르면 `run`(연구 목록은 설명을 본문에 펼침/접음, 터치용) |

- **고른 칸은 눌리지 않는다**: 서버 폼 버튼은 끌 수 없으므로, 고른 칸(`ItemSlot.Selected`, `§0§s§r`)은 같은 모양의 버튼에 눌러도 폼에 답하지 않는 이름(`button.df_noop`)을 단다(`gslot_sel_button`). 호버 툴팁은 그대로 뜬다. 고른 탭(`tab_button_on`, 발전과제 트리의 `tree_tab_button_on`)과 세이브 선택의 고른 줄(`list_row_button_on`)도 같다. 같은 화면을 다시 보낼 뿐인 칸(고른 연구, 도감의 지금 보기)을 고른 칸으로 둔다. 칸마다 버튼은 하나다: 누르는 버튼과 누르지 않는 버튼을 칸마다 둘 다 두면 컨트롤이 두 배가 되어 연구 화면이 열리는 데 몇 초 걸린다. 채움 칸·틀·화살표·글처럼 버튼이 아닌 칸은 처음부터 그림이라 눌리지 않는다. 연구 화면의 재료·보상 칸(고정 32칸)만 `Run` 이 없는 칸을 누를 수 없는 버튼으로 그린다(버튼 글 11번째 바이트 `v`).

- **호버 상자는 엔진 툴팁이다**: 칸 옆에 직접 그린 상자는 칸 줄을 감싼 스크롤 창에 잘리고 방향(`l`/`r`)을 따로 정해야 했다. 지금은 바닐라 `common.hover_text`(`hover_text_renderer`, 인벤토리 아이템 툴팁과 같은 렌더러)를 호버·선택 상태의 자식으로 두고 `#hover_text` 에 버튼 글(칸은 20바이트 뒤, 서랍 창 칸은 전부)을 넣는다(`gslot_hover_tip`, `slot_tooltip`). 엔진이 포인터 옆에 그리므로 창에 잘리지 않고 방향이 없다. 버튼 글의 호버 쪽 1바이트(`l`/`r`)는 자리만 남아 있고 쓰지 않는다. 줄바꿈은 글에 넣은 `\n` 에서만 한다(`$hover_text_max_width` 0; 150 으로 두면 한글이 5자쯤에서 꺾였다).
- **줄바꿈 격자의 버튼 순서**: 격자는 숨겨진 버튼도 칸을 차지하므로 탭·뒤로가기 같은 표식 버튼은 **칸 뒤에** 둔다(`ui.ItemGrid`). 앞에 두면 칸이 오른쪽으로 밀려 시작하고(15차 실기) 칸 번호(`i%11`)로 정하는 호버 방향도 어긋난다.
- **열 때 호버 상자가 켜져 있던 문제**: 바닐라 `common.toggle` 은 라디오 그룹에서 `$toggle_group_default_selected` 가 0 이라 첫 칸이 처음부터 선택돼(터치) 그 칸의 상자가 떴고, `common.button`·`common.toggle` 은 `focus_enabled` 가 켜져 있어 처음 포커스가 간 칸이 호버 상태로 그려질 수 있다(키보드·컨트롤러 포커스). 폼의 모든 버튼(도움말·뒤로·탭·목록·카드·칸·눌림)은 `$focus_enabled: false`, 라디오 토글은 `$toggle_group_default_selected: -1`, `$toggle_focus_enabled: false` 로 둔다. 안 그러면 모바일에서 폼을 열 때 첫 버튼(제목 막대의 "?")에 포커스가 가 호버 상자가 떠 있었다. 이 버튼들은 컨트롤러 포커스 이동을 받지 않는다.
- **터치에서 상자가 겹치던 문제**: 라디오 토글은 형제 컨트롤끼리만 한 그룹이고, 격자 칸은 칸마다 따로 부모가 있어 배타적이지 않았다(칸을 누르는 대로 상자가 쌓였다). 격자 칸(`gslot_*`, `cols_*`)은 터치에서도 일반 버튼이라, 손가락을 누르고 있는 동안 상자가 뜨고 떼면 실행된다. 라디오 토글은 형제인 서랍 창 칸에만 남았다.
- **호버 상자 모양**: 엔진 툴팁의 바닐라 모양(어두운 보라 테두리)을 그대로 쓴다. 글 색은 버튼 글의 `§` 코드가 정한다.
- 연구 창의 왼쪽 카드는 표식 `§0§i§r` 버튼 하나다(`ui.Detail`): 아이콘은 `gdetail_icon_item`, 이름·상태 글자는 `gdetail_name_item`, 그 사이 동작 버튼은 기존 `marked_actions`. 줄 제목은 `§0§g§r`(줄 A), `§0§h§r`(줄 B) 표식 버튼이다.
- 동작 버튼(`§0§4§r`, 뒤로 `§0§3§r`)은 칸보다 **앞에** 보내 버튼 번호가 칸 수에 상관없게 한다(시나리오가 `연구 진행` 을 0번으로 누른다).
- 마우스: `gslot_button` 의 hover/pressed 상태가 `gslot_face_tip`(호버 상자 포함). 터치: 같은 버튼(누르고 있는 동안 상자, 떼면 실행).
- 줄바꿈 격자는 **동작·뒤로 버튼도 격자 칸 하나씩 차지해** 마지막에 빈 칸이 생긴다(표 폼과 같음). 줄 A·B 스택은 숨은 컨트롤이 자리를 차지하지 않는다.
- 새 칸 종류를 만들면 표식을 쓰는 곳(`vis_gslot_*`, 제목 표식 제거, `server_form.json` 분기)을 모두 맞춘다.

### 폼 성능 (바인딩 조건)

서버 폼에는 레이아웃을 고르는 공식 방법이 없어, `server_form.json` 은 레이아웃(목록·카드·표·서랍·연구·도관 설정)을 제목 표식으로 고른다. 숨기기만 하면 숨긴 레이아웃도 버튼마다 컨트롤을 만들어 폼이 길수록 몇 초 멈춘다. 그래서:
- 레이아웃마다 `server_form.json` 에 하나씩만 두고, 그 레이아웃을 켜는 제목 표식 조건은 `"binding_condition": "always"` 로 매 프레임 평가한다. `once` 로 두면 폼이 다음 폼으로 바뀌는 사이 잠깐 맞았던 레이아웃이 켜진 채 남아 다음 폼 위에 겹친다.
- **레이아웃은 숨김(`"visible": false`)으로 시작하고, 팩토리·격자의 길이 바인딩은 `"binding_condition": "visible"` 로 평가한다.** 제목 표식이 맞는 레이아웃만 켜져서 그때 버튼을 만들고, 숨은 레이아웃은 한 번도 평가되지 않아 버튼을 만들지 않는다(실기 확인). 처음부터 보이는 레이아웃에 `visible` 조건을 쓰면 숨은 레이아웃도 첫 프레임에 버튼을 만들어 렉이 났다. 같은 구조에서 `always_when_visible`·기본(`always`)은 만들어진 버튼의 글자·표식이 비었다. 버튼 단위 바인딩에는 조건을 붙이지 않는다.
- 제목으로 켜지는 팩토리 게이트(`collection_panel` + `factory`)는 게이트 안에서 팩토리·격자가 폼의 버튼을 못 읽고 고정 위치 칸(`collection_index`)만 읽어서 쓰지 못한다(실기 F1~F7). 목록 게이트가 제목이 비었을 때 두 번째 창을 만든 적도 있다.
- 실기로 얻은 제약:
  - 팩토리·격자 길이를 `#form_button_contents`·`#form_button_length` 로 계산(`* 1` 포함)하면 팩토리는 버튼이 안 생기고, 격자는 계산식(`* (제목 표식 일치)`)이 된다.
  - 팩토리 길이에 `always_when_visible` 을 붙이면 첫 프레임에 만든 버튼의 바인딩이 갱신되지 않아 표식 판별·글자가 비고 창을 바꾸거나 눌러야 정상이 된다. `visible`·`visibility_changed` 는 첫 프레임은 정상이나 숨은 레이아웃을 막지 못했다.
  - 표식은 식에 글자로 적는다(변수는 식 안에서 바뀌지 않는다).
- 새 레이아웃·버튼 틀을 만들 때도 같은 규칙을 따른다. 판단은 Go 가 표식으로 미리 정하고 UI 는 단순 비교만, 긴 목록은 서버에서 쪽을 나눈다.
- 레이아웃이 비거나 버튼 글자·아이콘이 안 나오면 이 조건부터 의심한다.

## 창 크기

- **어떤 폼 창도 바닐라 인벤토리 화면(326×166)보다 크지 않다.** 터치 화면은 UI 를 더 크게 그려서, 이 크기를 넘는 창은 휴대폰 화면에 들어가지 않는다. 탭과 컨트롤 막대는 인벤토리의 도구 막대처럼 창 위에 붙는다. 새 레이아웃도 이 안에서 만들고, 넘치면 서버가 쪽을 나눈다.
- 아이템 칸은 인벤토리처럼 18px 이다(칸 격자·상세의 재료 줄·도관 설정·연구 격자).
- 제목은 막대 없이 창 위 가운데 한 줄(10px)이고, 내용은 창 위 18px 에서 시작한다(바닐라 상자 제목과 같은 자리).
- 모든 폼 창은 화면 비율이 아니라 **고정 픽셀 크기**다. `100%c` 로 내용 높이를 재면 창과 내용이 서로를 참조해 크기가 무너지고(버튼이 창 밖으로 나감), 화면 비율(`65%`~`80%`)은 짧은 목록에서 위아래 빈 공간을 남긴다.
- 레이아웃별 크기: 목록 230×166, 카드 296×166(제목 없는 로비 카드 296×124), 상점 318×166, 표 322×166, 상세·도관 설정·연구 분할·발전과제 트리 326×166, 줄바꿈 격자 224×166, 서랍 220×136, 세이브 326×126, 입력 260×96.
- 탭은 아이콘만 있는 24×22 칸이고 글은 포인터를 올리면(터치는 누르고 있는 동안) 엔진 툴팁으로 뜬다(창조 인벤토리 탭처럼). 연구 화면의 두 탭만 글과 개수가 보이는 96px 탭이다.
- 폼 창은 애니메이션 없이 바로 나타난다(창이 움직이는 동안 다음 폼이 오면 두 창이 겹쳐 보인다).
- 내용이 넘치면 스크롤이 아니라 **서버가 쪽을 나눈다**(칸 격자 한 쪽 44칸 등). 새 레이아웃을 만들면 그 화면의 최대 내용 높이를 재서 고정 크기를 정한다.

## 기계 창

- 기계 인벤토리는 그대로 엔티티 상자(`chestui.Storage`, 27칸). 제목 표식으로 기계별 레이아웃을 골라 입력·진행·출력·회수 칸만 보인다.
- 진행도 칸에는 `dragonfactory:progress_0`~`progress_10` 아이템(채워지는 화살표)이 들어가 화살표가 차오르는 것처럼 보인다.
- 창 오른쪽 위 어두운 컨트롤 막대(`df_machine.control_bar`)에 닫기 버튼 왼쪽으로 26번(정보 아이콘, 툴팁이 기계 설명)이 칸 배경 없이 18×18로 놓인다.
- 모두 꺼내기·모두 넣기는 모든 창고와 같이 창 오른쪽 바깥의 세로 버튼 줄(common inventoryui `df_quick.side_bar`)이다. 버튼 밑에 칸마다 보이지 않는 버튼을 겹쳐 두고, 각각 누름을 그 칸의 바닐라 빠른 이동(`button.container_auto_place`, `consume_event: false`)으로 바꾸므로 클릭 한 번이 모든 칸의 쉬프트 클릭이 된다(Quick Container 팩의 기법, 코드는 쓰지 않음). 기계 창은 `$df_machine_outputs` 식으로 꺼낼 칸을 거른다. 있는 것만 넣기는 인벤토리 칸의 숨은 버튼이 이름 붙은 창고 칸 컨트롤(`df_quick_c<n>`)의 `#item_id_aux` 를 `source_control_name` 으로 읽어(화면 루트부터 첫 일치) 같은 것이 있을 때만 보인다(`#visible`). 툴팁은 버튼 hover 상태 안의 라벨이라 번역 키가 풀린다(`common.hover_text` 의 `#hover_text` 는 번역되지 않음).
  - `collection_index` 는 `collection_name` 을 가진 요소의 바로 아래 자식에서만 먹는다. `collection_panel` 안의 `stack_panel` 자식에 쓰면 "Unknown property [collection_index]" 오류가 나므로, `stack_panel` 자체에 `"collection_name": "container_items"` 를 준다.
- 모양은 바닐라 화로 화면과 같다: 밝은 회색 창(`textures/ui/dialog_background_opaque`), 바닐라 칸(`textures/ui/cell_image`), 진한 회색 제목(바닐라 `$title_text_color` 그대로)은 화로 화면(`furnace_label`)처럼 창 위 가운데 4px 아래. 제목 표식 `§d§m§<n>` 의 마지막 코드는 색 코드라 Go 가 표식 뒤에 `§r` 을 붙인다. 출력이 하나인 기계(분쇄기·전기 화로·합금로)의 출력 칸은 화로 결과 칸처럼 26×26. 진행도 칸은 칸 배경 없이 그림만이고, 화살표·링·배터리의 빈 부분은 바닐라 화로 화살표(`arrow_inactive`)와 같은 밝은 회색, 찬 부분은 흰색·주황이다. 정보 아이콘은 창 오른쪽 위 어두운 컨트롤 막대에 흰 그림으로, 모두 꺼내기·모두 넣기는 창 오른쪽 바깥에 바닐라 밝은 버튼으로 있다.
- 모바일용 기계 레이아웃은 만들지 않는다(사용자 결정, 6차 실기).

## 로비 입장기 틀

로비를 게임 입장기처럼 보이게 하는 화면 전체의 틀(`ui/df_lobby.json` 의 `df_lobby.frame`, 테마의 `dfui_hooks.lobby_frame` 을 채운다): 왼쪽 위에 게임 아이콘(풀 블록 옆면)과 이름(`df.lobby.title`, MinecraftTen 글꼴), 그 아래 옅은 1px 선. 나머지는 비워 고정 카메라로 비춘 로비 섬이 보인다(`internal/platform/lobby.go`). 바닐라 HUD 는 `SetHud` 로 숨기고(`dfhook.HideHUD`), 틀은 리소스팩 HUD 부분이라 남는다.

- HUD: 로비에서는 사이드바 목표 이름이 `hud.FrameTitle`(`§d§h§u§d§d§l§b`)이고 `scoreboards.json` 이 그 표식으로 틀을 그리고 퀘스트 창을 숨긴다. 줄이 없어도 사이드바가 보이도록 아무 부분에도 속하지 않는 줄 `§d§0` 하나를 보낸다. 운영자 부하 줄은 그대로 왼쪽 위에 겹친다. 바뀔 때만 보내고(`internal/platform/load.go`), 로비에 도착할 때마다 다시 보낸다.
- 폼: 폼이 열려 있는 동안 HUD 는 그려지지 않으므로 폼 화면도 같은 틀을 그린다. 로비에 있는 플레이어에게 보내는 모든 폼 제목에 `§d§f§w§r`(`ui.LobbyToken`, `ui.InLobby` 로 판별)이 붙고, `server_form.json` 이 `third_party_server_screen` 의 `$screen_bg_content`(안전 영역 밖 배경, 화면 전환 때 밀려나지 않는다)를 `dfui_hooks.form_frame` 으로 바꿔 그 표식이 있으면 틀(`dfui_hooks.lobby_frame`)을 그린다. 이 배경에서는 `#title_text` 바인딩을 `once` 로 두면 폼 내용이 오기 전에 평가돼 보이지 않으므로 조건 없이 계속 평가한다. 배경 애니메이션(`$background_animations`)은 비워 폼을 바꿀 때 틀이 깜빡이지 않는다. 로비 폼은 창 둘레를 어둡게 하지 않는다(`df_form.window` 의 `dim`).
- 메인 메뉴(`ui.LauncherMenu`, 제목 표식 `§d§f§n§r`): 창 없이 이름 아래(왼쪽 16, 위 54)에 큰 버튼(150×24, 간격 4)이 세로로 놓인다(`df_form.launcher_form`). 버튼은 반투명 어두운 바탕·옅은 테두리(`launcher_button`, 호버는 파란 테두리), 흰 선 아이콘(`icon_cube` 등, `common/tools/uitextures`), 이름, 꺾쇠(`chevron_right`)다. 버튼 글은 팩 언어 키(`df.lobby.single` 등)이고 라벨이 `localize` 로 번역한다.
- HUD 의 메인 메뉴 그림: 테마의 `dfui_hooks.lobby_menu`(HUD 에만, 틀과 같은 조건)를 서버 팩이 `df_lobby.menu` 로 채운다. 같은 자리(`df_form.launcher_column`)에 같은 모양의 그림 버튼(`df_form.launcher_static`)을 같은 키·아이콘·순서로 그린다(`platform` 의 `lobbyMenu` 와 맞는지 `lobbymenu_test.go` 가 검사). 그래서 메뉴 폼을 닫아도 화면이 같다. 플레이어가 닫은 폼은 다시 보내지 않고, 다음 행동에서 메인 메뉴를 연다(`internal/platform/lobbywake.go`): 클릭·핫바·점프·공격은 로비 핸들러가, 이동 키·점프·웅크리기는 이동이 잠겨 있어 패킷 훅이 `PlayerAuthInput` 의 `RawMoveVector` 와 입력 플래그로 본다(플레이어마다 0.3초에 한 번). 이미 열린 메뉴는 ui 의 같은 폼 반복 방지로 다시 가지 않는다.
- 제목 없는 카드 폼(`ui.CardMenu` 에 빈 제목 → `§d§f§u§r`, `ui.UntitledToken`): 제목 막대 없이 내용이 창 위 10px 에서 시작하고 창이 그만큼 낮다(`cards_u`·`cards_us`, 296×124).

## 폼 동작의 알림

폼이 열려 있으면 채팅이 보이지 않으므로 알림은 **토스트**(화면 위 알림창)로 보낸다. 폼 위에도 보이고 다음 폼을 막지 않는다(`common/ui`).

- `ui.Notify`(실패 등 지금만 필요한 알림: 재료 부족 …): 토스트만. 제목 `알림`(빨강).
- `ui.Flash`(결과가 중요한 알림): 토스트 + 같은 줄을 채팅에도(나중에 다시 읽기). 제목 `완료`(초록).
- 폼 동작 안이든 밖(명령어·아이템 사용)이든 바로 보낸다.
- 로비에는 채팅이 없어 `ui.Flash` 는 토스트만 보내고, 채팅으로 보낼 글은 `ui.Tell`(세이브 안이면 채팅, 로비면 토스트 `알림`)로 보낸다. 업적 달성도 로비에서는 토스트(`업적 달성`)다.
- 클라이언트는 토스트를 하나씩 차례로 보여 주므로, 플레이어마다 **`ui.ToastGap`(3초)에 하나**만 보낸다:
  그 사이에 온 알림은 하나로 합쳐 앞 토스트가 끝날 때 가장 최근 메시지 + `(외 n건)` 으로 보낸다. 성공 메시지는 채팅에 전부 남는다. 토스트가 실제로 떠 있는 시간에 맞춰 간격을 조정한다.
- 시나리오 봇은 토스트도 `expect:` 로 받는다. 늦게 온 토스트를 기다리는 동안 지나간 폼은 버리지 않고 다음 `form:` 단계에 넘긴다.

## 같은 폼 반복 방지

클라이언트는 아이템 사용 버튼을 누르고 있는 동안 사용 패킷을 반복해서 보낸다. 그대로 폼을 보내면 같은 폼이 여러 개 쌓여, 하나를 닫을 때마다 다음 것이 다시 뜬다.
- `common/ui` 는 답하지 않은 같은 제목의 폼이 3초 안에 있으면 새로 보내지 않는다(제출·닫기 때 해제).
- 메뉴 아이템 사용은 0.5초 디바운스.

## HUD(사이드바 줄을 나눠 그리기)

왼쪽 위(일차·플레이 시간, 운영자 부하 줄), 오른쪽 가운데 퀘스트 창(다음 발전과제)을 **사이드바 스코어보드 한 장**으로 보낸다(`common/hud`). 제목(title)은 WAILA 가 쓰고 한 번에 하나만 담겨서, 늘 떠 있어야 하는 글자를 같이 실으면 서로 덮는다. 사이드바 줄은 바꾸기 전까지 남아 있다.

- 서버: 목표(objective) 이름 `§d§h§u§d`, 줄마다 부분 표시를 앞에 붙인다: `§d§1` 왼쪽 위, `§d§2` 오른쪽 위, `§d§3` 퀘스트 제목, `§d§4` 퀘스트 줄. 줄 순서는 부분 안에서 그대로. Dragonfly 의 앞 공백(padding)은 끈다. 같은 글자 줄은 클라이언트가 합치므로 뒤에 `§r` 를 붙여 구분한다. 최대 15줄.
- 팩: `common/packs/dfui/ui/scoreboards.json` 이 바닐라 `scoreboard.scoreboard_sidebar` 를 화면 전체 패널로 바꾸고, 목표 이름에 표시가 있으면 `df_hud`, 없으면 단순한 상자(`df_plain_sidebar`, 다른 보드용)를 보인다. 부분마다 `scoreboard_players` 컬렉션 스택(`#scoreboard_sidebar_size` → `#collection_length`)을 두고, 줄 라벨은 `#player_name_sidebar` 에 그 표시가 있을 때만 보이며 표시를 뺀 글자를 쓴다. 바닐라 이름은 Mojang `bedrock-samples` `resource_pack/ui/scoreboards.json` 에서 확인했다. 라벨은 `localize: false`(번역을 거치면 `%` 가 사라진다).
- 숨겨진 줄은 스택에서 자리를 차지하지 않는다고 보고 짰다(실기 확인 필요).
- 경험치 바는 바닐라 그대로다.
- 분할·트리 폼의 왼쪽/오른쪽 판은 `panel` 안에 왼쪽 위 기준(오른쪽은 `offset` 220)으로 둔다. 가로 스택은 `100%c` 가 높이를 더하고 `100%cm` 은 오른쪽 상세를 접어 버려, 높이가 큰 쪽을 따르는 `panel` 의 `100%c`(자식 범위)를 쓴다.
- 글자 비교로 보이기를 정할 때는 먼저 글자를 `#변수`에 담고 `(not (#변수 = 'z'))` 로 비교한다. `(not ((A - B) = 'z'))` 처럼 식 안에서 바로 비교하면 실기에서 참·거짓이 뒤집혔다(발전과제 트리: 노드가 있는 칸이 숨고 빈 칸이 보였다).

## HUD (터치의 포켓 배치)

터치 화면에서 UI 프로필이 포켓이면 바닐라 HUD 가 `not_centered_gui_elements` 를 써서 하트를 왼쪽 위, 배고픔을 오른쪽 위에 그린다. 그 자리는 이 서버의 일차·플레이 시간 줄과 겹치므로, `common/packs/dfui/ui/hud_screen.json` 이 그 판을 다시 정의해 하트·갑옷·배고픔·공기 방울·탈것 하트를 핫바 위(클래식 터치 배치, 바닐라 `centered_gui_elements_at_bottom_middle_touch` 와 같은 위치)에 둔다. 핫바는 포켓 배치가 따로 그리므로 넣지 않고, 종이 인형만 왼쪽 위에 남는다.

## 흑백 PNG

클라이언트는 흑백(grayscale) PNG 를 반투명하게 그린다(발전과제의 회색 노드 틀과 창이 비쳐 보였다). 텍스처 최적화 도구가 회색 그림을 흑백으로 바꾸므로, 팩의 PNG 는 RGB·RGBA 로 둔다. 최적화한 뒤 `file` 로 grayscale 이 없는지 본다.
