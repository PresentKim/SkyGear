# JSON UI (드래곤팩토리 테마)

폼과 기계 창의 모양은 리소스팩 JSON UI 로 바꾼다. 서버는 폼 내용만 보내고, 모양은 클라이언트가 팩으로 그린다.

## 파일

| 파일 | 내용 |
|---|---|
| `assets/resourcepack/dragonfactory/ui/server_form.json` | 바닐라 `server_form.main_screen_content`(전체 화면으로)·`long_form`·`custom_form` 을 덮어써 모든 서버 폼을 어두운 테마로. 제목 앞 표식으로 분기: `§d§f§c§r`(`ui.CardToken`) 카드 격자, `§d§f§s§r`(`ui.ShopToken`) 촘촘한 상점 격자, `§d§f§t§r`(`ui.TableToken`) 표, `§d§f§i§r`(`ui.SlotToken`) 인벤토리처럼 보이는 칸(보이기만 하는 보관 칸 `§0§9§r`과 옆 글 `§0§b§r`, 누르는 왼쪽 칸 `§0§a§r`·오른쪽 칸 `§0§c§r`, 서랍 창; 칸 글자가 안내 문구 — 마우스는 hover·pressed 상태에 안내 상자, 터치(`$touch`)는 바닐라 라디오 토글로 첫 탭 선택·안내, 선택된 칸 위에만 진짜 버튼이 있어 다시 탭하면 실행). 폼은 누른 버튼을 글자로 찾으므로 같은 글자의 버튼은 `ui.Menu` 가 `§r` 을 붙여 구별한다, 없으면 목록 |
| `assets/resourcepack/dragonfactory/ui/df_form.json` | 테마 컨트롤(`df_form` 네임스페이스): 창(패널·제목 막대·닫기), 목록 버튼(아이콘+글자), 카드 격자, 입력 폼 |
| `assets/resourcepack/dragonfactory/ui/df_machine.json` | 기계 창 레이아웃(`df_machine`): 바닐라 작은 상자 화면에서 그 기계의 칸만 정해진 위치에 |
| `assets/resourcepack/inventoryui/ui/chest_screen.json` | 제목 표식 `§d§m§1`~`§d§m§5` 이면 기계 창으로 분기(PC 화면만, 모바일은 크기 지정 상자 그대로) |
| `assets/resourcepack/dragonfactory/textures/ui/df/*` | 테마 텍스처. `go run ./tools/uitextures` 로 다시 만든다(색은 그 파일 위쪽) |

## 폼 (메뉴·확인·입력)

- 항목을 넣고 빼지 않는 메뉴는 **폼**으로 만든다(상자 아님): 드래곤팩토리 메뉴, 상점 구매·판매, 분실물 보관함, 섬 확장 지도 등.
- 카드 격자 폼(`ui.CardMenu`): 아이콘 위·글자 아래 카드가 한 줄에 3개(90px 칸, 격자 폭 270px 고정·가운데), 버튼 수만큼 줄이 늘어난다(스크롤). 메뉴(3×4)·판매·분실물. 상점 구매는 촘촘한 격자(`ui.ShopMenu`).
  - 격자 항목 수는 `#form_button_length` → `#maximum_grid_items`, 격자 높이는 `100%c` 로 묶는다(`#form_button_contents` 나 `default` 높이면 버튼이 하나도 안 생긴다 — 6차 실기).
- 목록 폼(`ui.Menu`): 버튼마다 아이콘(`ui.Option.Icon`) + 글자. 아이콘은 두 가지:
  - `textures/...` 로 시작하는 텍스처 경로: 이미지로 그린다(메뉴 항목 등 아이템이 아닌 것).
  - **아이템**: `ui.ItemIcon`(`dragonfactory.iconOf`)이 아이템 런타임 ID × 65536 을 숫자 문자열로 넣는다. 테마의 `button_icon_item`(`inventory_item_renderer`)이
    그 값을 `#item_id_aux` 로 받아 인벤토리 칸처럼 아이템을 직접 그린다. 블록은 블록 모양 그대로, 아이콘 텍스처 경로를 따로 관리할 필요가 없다(빠진 경로 때문에 아이콘이 안 보이던 문제 해결).
    패키지 변수 초기화 때 만들면 안 된다: 아이템 등록(`init`) 전이라 런타임 ID 가 없어 빈 아이콘이 된다(상점 탭, 10차 실기). 폼을 만들 때 계산한다.
    방식은 Chest-UI 와 같고, `#item_id_aux` = ID × 65536 + 데이터값은 바닐라 `inventory_screen.json`·bedrock-wiki 표와 같다. 데이터값(메타)은 쓰지 않는다.
- 확인 폼(`ui.Confirm`)은 바닐라 modal 이 테마를 받지 않아(8차 실기: 밝은 기본 창) **목록 폼 두 버튼**(확인·취소)으로 보낸다. 닫기는 취소와 같다.
- 수량 폼(`ui.Amount`): 입력 폼(custom_form)의 슬라이더 하나.

### 버튼 표식 (탭·뒤로·표)

버튼 글자 앞의 표식(유효한 색 코드라 테마가 없어도 글자에 안 보임)으로 버튼의 자리를 정한다. 표식은 모두 `§0§` 로 시작하고, 목록·격자는 표식 있는 버튼을 숨긴다. 표식 버튼은 일반 버튼 **뒤에** 둔다(격자에서 숨긴 칸이 끝에만 생기게).

| 표식 | Go | 자리 |
|---|---|---|
| `§0§1§r` / `§0§2§r` | `ui.Tab(…, selected)` | 창 위쪽 탭 줄(선택된 탭은 밝게) |
| `§0§3§r` | `ui.Back` | 제목 막대의 닫기 버튼 왼쪽 작은 화살표 버튼 |
| `§0§4§r` | 표의 동작 버튼 | 표 아래 목록 버튼 |
| `§0§5§r`·`§0§6§r` | `ui.Cell` | 표의 칸(글자·숫자, 머리 칸은 회색 글자), 버튼이 아니라 눌리지 않음 |
| `§0§8§r` | 표의 합계 | 표 아래 오른쪽 주황 글자 |

- 탭 줄·뒤로 칸·합계·동작은 `df_form.marked_buttons`: 모든 버튼을 도는 가로/세로 스택 팩토리에서 그 표식 버튼만 보이게 한다(숨긴 컨트롤은 스택에서 자리를 차지하지 않음).
- 표(`ui.TableMenu`)는 4열(80px) 격자. 첫 열은 아이콘+이름, 숫자 열은 오른쪽 정렬. 전체 판매 확인에 쓴다.
- 상점(`ui.ShopMenu`)은 360px 창, 56×48px 칸 6열의 인벤토리 같은 작은 카드(아이콘·이름·가격). 격자 폭은 내용 영역(336px)을 넘으면 왼쪽 열이 잘린다.
- 탭 줄 높이는 `100%cm`(가장 큰 자식). 가로 스택의 `100%c` 는 자식 높이를 모두 더해 탭 아래에 큰 공백이 생겼다.
- 입력 폼(custom_form): 어두운 창 안에 바닐라 입력 칸 그대로(밝은 카드는 글자가 안 보여 뺐다).
- 폼 뒤를 어둡게 하는 배경은 화면 일부에만 그려져 뺐다.

### 폼 성능 (바인딩 조건)

서버 폼에는 레이아웃을 고르는 공식 방법이 없어, `server_form.json` 은 레이아웃(목록·카드·상점·표)을 **전부 만들고** 제목 표식으로 하나만 보인다.
숨긴 레이아웃도 버튼 목록 전체를 만들고, 바인딩은 기본값(`always`)이면 숨긴 컨트롤에서도 **매 프레임** 평가된다(제목 문자열 연산, 버튼마다 표식·아이콘 판별).
레이아웃·버튼이 늘수록 모든 폼이 그 곱만큼 느려지는 것이 흔히 말하는 "UI가 많아지면 폼이 렉" 문제다. 그래서:
- 제목으로 레이아웃을 고르는 바인딩과 제목 줄은 `"binding_condition": "once"`(폼이 열린 동안 제목은 안 바뀜).
- 버튼 단위 `collection`·`view` 바인딩(글자, 표식 판별, 아이콘, `#item_id_aux`)은 `"always_when_visible"`: 숨긴 레이아웃은 건너뛴다.
- 격자 칸 수(`#maximum_grid_items`, `#collection_length`, `collection_details`)는 조건 없이 둔다(배치를 정함).
- 새 레이아웃·버튼 틀을 만들 때도 같은 규칙을 따른다. 판단은 Go 가 표식으로 미리 정하고 UI 는 단순 비교만, 긴 목록은 서버에서 쪽을 나눈다.
- 레이아웃이 비거나 버튼 글자·아이콘이 안 나오면 이 조건부터 의심한다(`once` 가 데이터보다 먼저 평가되는 경우).

## 기계 창

- 기계 인벤토리는 그대로 엔티티 상자(`chestui.Storage`, 27칸). 제목 표식으로 기계별 레이아웃을 골라 입력·진행·출력·회수 칸만 보인다.
- 진행도 칸에는 `dragonfactory:progress_0`~`progress_10` 아이템(채워지는 화살표)이 들어가 화살표가 차오르는 것처럼 보인다.
- 26번 칸은 정보 아이콘: 제목 줄의 닫기 버튼 왼쪽(칸 배경 없음). 툴팁이 기계 설명.
- 배경은 폼과 같은 어두운 패널(`textures/ui/df/panel`)과 어두운 칸(`slot`), 제목은 주황 글자. 진행도 칸은 칸 배경 없이 화살표만(6차 실기 반영).
- 모바일용 기계 레이아웃은 만들지 않는다(사용자 결정, 6차 실기).

## 요령

- 8차 실기 뒤 겪은 오류: 팩토리 `control_ids` 에 변수(`$df_marked_template`)를 쓰면 "UI control reference not found". 크기 배열 안의 숫자 변수(`[ "$w", "100%c" ]`)는 "Dangling number" 이므로 크기는 배열 전체를 변수로(`"size": "$df_window_size"`). `grid_item_template`·상속한 `$scrolling_content` 같은 자리도 변수 대신 컨트롤을 따로 정의했다.

## 폼 동작의 알림

폼이 열려 있으면 채팅이 안 보인다(9차 전 실기). 알림은 **토스트**(화면 위 알림창)로 보낸다. 폼 위에도 보이고, 다음 폼을 막지 않는다(`internal/ui`, 10차 실기 요청).

- `ui.Notify`(실패 등 지금만 필요한 알림: 돈 부족, 재고 없음 …): 토스트만. 제목 `알림`(빨강).
- `ui.Flash`(구매·판매 성공 등 결과가 중요한 알림): 토스트 + 같은 줄을 채팅에도(나중에 다시 읽기). 제목 `완료`(초록).
- 폼 동작 안이든 밖(명령어·아이템 사용)이든 바로 보낸다. 예전의 "알림" 폼(확인 후 다음 폼)과 다음 메뉴 맨 위 결과 줄은 없앴다.
- 클라이언트는 토스트를 하나씩 차례로 보여서, 빠르게 여러 번 사고팔면 한참 밀려 나왔다(10차 실기). 그래서 플레이어마다 **`ui.ToastGap`(3초)에 하나**만 보낸다:
  그 사이에 온 알림은 하나로 합쳐 앞 토스트가 끝날 때 가장 최근 메시지 + `(외 n건)` 으로 보낸다. 성공 메시지는 채팅에 전부 남는다. 토스트가 실제로 떠 있는 시간에 맞춰 간격을 조정한다.
- 시나리오 봇은 토스트도 `expect:` 로 받는다. 늦게 온 토스트를 기다리는 동안 지나간 폼은 버리지 않고 다음 `form:` 단계에 넘긴다.

## 같은 폼 반복 방지

클라이언트는 아이템 사용 버튼을 누르고 있는 동안 사용 패킷을 반복해서 보낸다. 그대로 폼을 보내면 같은 폼이 여러 개 쌓여, 하나를 닫을 때마다 다음 것이 다시 뜬다(7차 실기 "폼이 계속 재표시").
- `internal/ui` 는 답하지 않은 같은 제목의 폼이 3초 안에 있으면 새로 보내지 않는다(제출·닫기 때 해제).
- 메뉴 아이템·수표 사용은 0.5초 디바운스.

## HUD(사이드바 줄을 나눠 그리기, 13차 뒤)

왼쪽 위(일차·플레이 시간, 운영자 부하 줄), 오른쪽 위(돈), 오른쪽 가운데 퀘스트 창(미션)을 **사이드바 스코어보드 한 장**으로 보낸다(`internal/hud`). 제목(title)은 WAILA 가 쓰고 한 번에 하나만 담겨서, 늘 떠 있어야 하는 글자를 같이 실으면 서로 덮는다. 사이드바 줄은 바꾸기 전까지 남아 있다.

- 서버: 목표(objective) 이름 `§d§h§u§d`, 줄마다 부분 표시를 앞에 붙인다: `§d§1` 왼쪽 위, `§d§2` 오른쪽 위, `§d§3` 퀘스트 제목, `§d§4` 퀘스트 줄. 줄 순서는 부분 안에서 그대로. Dragonfly 의 앞 공백(padding)은 끈다. 같은 글자 줄은 클라이언트가 합치므로 뒤에 `§r` 를 붙여 구분한다. 최대 15줄.
- 팩: `dragonfactory/ui/scoreboards.json` 이 바닐라 `scoreboard.scoreboard_sidebar` 를 화면 전체 패널로 바꾸고, 목표 이름에 표시가 있으면 `df_hud`, 없으면 단순한 상자(`df_plain_sidebar`, 다른 보드용)를 보인다. 부분마다 `scoreboard_players` 컬렉션 스택(`#scoreboard_sidebar_size` → `#collection_length`)을 두고, 줄 라벨은 `#player_name_sidebar` 에 그 표시가 있을 때만 보이며 표시를 뺀 글자를 쓴다. 바닐라 이름은 Mojang `bedrock-samples` `resource_pack/ui/scoreboards.json` 에서 확인했다. 라벨은 `localize: false`(예전 사이드바에서 `%` 가 사라졌다).
- 숨겨진 줄은 스택에서 자리를 차지하지 않는다고 보고 짰다(실기 확인 필요).
- 레벨은 경험치 레벨, 미션 진행은 경험치 바(`SetExperienceLevel`/`Progress`, 경험치 획득은 막음).
