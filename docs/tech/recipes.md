# 레시피 잠금·실시간 개방 (연구 시스템 기술 검증)

참나무 판자·조합대·연구대를 뺀 모든 레시피를 잠그고 연구로 하나씩 연다. 게임 안에서 바로 열 수 있는지 확인한 결과다.

## 결론: 가능 (실기에서 작동 확인)

- 클라이언트는 서버가 `CraftingData` 로 보낸 레시피만 안다(레시피 책, 조합 칸 결과). 이 패킷은 `ClearRecipes` 로 **언제든 다시 보내 목록을 통째로 바꿀 수 있다.**
- Dragonfly 는 접속 때 한 번 전체 목록을 보내고, 세션마다 `네트워크 ID → 레시피` 표를 만들어 조합 요청(`CraftRecipe`·`AutoCraftRecipe`·대장장이·석재 절단기)을 그 표로만 받는다. 표에 없는 ID 는 동적 레시피(장식 항아리)로 넘어가고 거기도 없으면 거절.
- Dragonfly 패치 `Player.SetRecipeFilter(f)`: 필터가 고른 레시피만 보내고 표에 넣는다(네트워크 ID 는 전체 목록 순번 그대로라 바뀌지 않음). 부르면 바로 다시 보낸다. 필터가 있으면 동적 레시피는 막는다.
  - 따라서 잠긴 레시피는 레시피 책·조합 칸에 안 나오고, 패킷을 위조해도 서버가 거절한다.
- 시나리오 `spike/scenarios/recipes.sh`: 막대기 연구 뒤 받는 레시피가 두 자리 수 이하, `/dfadmin research free` 로 수백 개, 다시 잠그면 줄어듦, 연구 창에서 상자 연구를 판자로 납품해 완료(봇이 `CraftingData` 를 `recipes=<n>` 로 셈).
- 연구 시스템(기획 §3.4)이 이것을 쓴다: 섬에 들어오면 열린 결과(기본 + 완료한 연구)의 레시피만 보내고, 연구가 끝나면 섬의 모두에게 바로 다시 보낸다. 나가면 필터를 푼다. 코드 `dragonfactory/recipes.go`, `research.go`. 열기 단위는 결과 아이템 이름(색·나무 종류 구분 없이 함께 열림).

## 실기로 볼 것
- 조합대를 연 채 레시피를 열면 바로 레시피 책·조합 결과에 반영되는지(다시 열어야 하는지).
- 레시피 책 "새 레시피" 표시(`UnlockedRecipes` 패킷, 바닐라 레시피 해금 연출)는 아직 안 씀. 원하면 다음에 시험.

## 레시피 목록에 없는 것(따로 막아야 함)
- **화로·훈연기·용광로 굽기**: Dragonfly 는 레시피 목록이 아니라 아이템의 `Smeltable` 로 굽는다. 잠그려면 화로에 넣을 때·구울 때 검사를 따로 둔다.
- 우리 기계(분쇄기·체 등)의 가공은 우리 코드라 연구 상태를 직접 보면 된다.
- 양조(물약)는 목록에 있어 같이 잠긴다.

## 우리 아이템의 레시피가 제작 목록에 안 보이던 문제 (14차)

- 증상: 연구로 연 망치·체 레시피가 조합대의 제작 목록에 나오지 않음. 서버는 레시피를 보내고 있었다(`spike/scenarios/hammer_recipe.sh`: 봇이 아이템 레지스트리로 결과 아이템을 풀어 `RECIPE dragonfactory:hammer` 를 확인).
- 원인(추정): 클라이언트의 레시피 책은 **창작 인벤토리 목록**(`CreativeContent`)에 있는 아이템의 레시피만 나열한다. 바닐라 결과 아이템은 창작 목록에 있지만 우리 커스텀 아이템·블록은 없었다.
- 조치: `creative.go` 가 게임 시작 때 우리 아이템·블록을 창작 인벤토리에 등록한다(머리 없는 익명 그룹, 탭은 건축·장비·아이템). `TestEveryGameRecipeResultIsCreative` 가 우리 레시피의 결과가 모두 창작 목록에 있는지 검사한다. **새 아이템·블록을 레시피로 만들 때는 `creative.go` 에도 넣는다.**
- 실기 확인 전에는 미완료(TODO 7번): 서버가 보내는 데이터는 확인했지만 클라이언트 화면은 아직 못 봤다.

## 레시피 책에 바닐라 블록 레시피가 안 보이던 문제 (15차)

클라이언트 레시피 책은 레시피 결과가 창작 인벤토리의 항목과 **블록 상태까지** 같을 때만 그 레시피를 나열한다. 우리 아이템·블록은 창작 항목과 같은 방식으로 만들어 맞았지만, 바닐라 레시피 데이터(`crafting_data.nbt`)의 블록 결과는 상태가 다른 것이 많았다(상자: 레시피 18446, 창작 18448 등 30여 종). 그래서 상자·퇴비통 같은 바닐라 블록이 제작 목록에 없었다. Dragonfly 패치 `creativeBlockFitter` 가 레시피 결과의 블록 런타임 ID 를 창작 항목의 것으로 맞춘다. 시나리오 `recipe_book.sh`(봇 `BOT_DUMP_RECIPES=1`)가 어긋난 결과(`MISMATCH`)가 없는지 확인한다.
