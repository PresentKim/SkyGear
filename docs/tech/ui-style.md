# UI 스타일 가이드

창·탭·컨트롤 막대·칸은 바닐라 그림을 가리켜 쓴다([vanilla-ui.md](vanilla-ui.md)).

폼·기계 창·HUD 의 모양과 쓰는 규칙. 구현 세부(표식, 바인딩)는 [json-ui.md](json-ui.md), 칸 장식은 [slotdeco.md](slotdeco.md), 성능 규칙은 [codex-jei.md](codex-jei.md).

## 팔레트

게임 기본 화면 같은 **회색 테마** 하나를 쓴다. 색은 `tools/uitextures/main.go` 위쪽 한 곳에서 정한다(없는 것만 만든다, `-f` 는 모두).

| 쓰임 | 색 | 값 |
|---|---|---|
| 창 바탕 | 밝은 회색 + 검은 테두리, 위·왼쪽 흰 선, 아래·오른쪽 어두운 선 | `(198,198,198)` / `(255)` / `(85)` |
| 제목 | 제목 막대 그림 없이 창 위에 가운데 정렬한 어두운 글자 | 글자 `0.2` |
| 버튼 / 호버 / 눌림 | 중간 회색 / 푸른 기 도는 밝은 회색 / 어두운 회색(들어간 모양) | `(66)` / `(84,84,128)` / `(48)` |
| 탭 / 선택된 탭 | 중간 회색 / 창과 같은 색으로 아래가 열림 | `(150)` / `(198)` |
| 칸(아이템 슬롯) | 중간 회색, 위·왼쪽 어두운 선, 아래·오른쪽 흰 선(들어간 모양) | `(139)` / `(55)` |
| 입력 칸 바탕 | 어두운 안쪽 테두리(게임 기본 입력 칸의 흰 글자용) | `(60)` |

글자: 창 위의 글은 어두운 회색(`0.2`), 버튼 위의 글은 흰색이다. 코드의 색 코드(`§f` 이름, `§7` 보조, `§8` 흐린 보조, `§e` 머리글, `§a` 좋음, `§c` 나쁨)는 **어두운 배경 기준**으로 적혀 있어서, 창 위에 바로 그려지는 글(본문, 표의 칸·합계, 머리글, 상세 카드)은 `ui.OnPanel`(`theme.go`)이 어두운 변형으로 바꾼다(`§f→§0`, `§7→§8`, `§8→§7`, `§e→§1`, `§6→§4`, `§a→§2`, `§b→§3`, `§c→§4`, `§d→§5`). 버튼 위 글과 툴팁(게임이 어두운 상자로 그린다)은 그대로 둔다. 등급 색은 이름에만 쓴다(`§a` 고급, `§b` 희귀, `§d` 영웅, `§6` 전설).

발전과제 트리 화면은 같은 회색 계열을 쓰되 창을 따로 그린다([advancement-tree.md](advancement-tree.md)).

## 화면의 종류

| 종류 | Go | 쓸 때 |
|---|---|---|
| 카드 격자 | `ui.CardMenu` | 같은 무게의 갈래 6~12개(메뉴, 도움말, 도감 첫 화면) |
| 목록 | `ui.Menu` | 항목이 글 위주이고 몇 개~수십 개 |
| 표 | `ui.TableMenu` | 열이 있는 숫자 |
| 칸 격자 | `ui.ItemGrid`, `ui.ItemGridSections` | 아이템이 주인공(스토리지, 도감 검색, 연구) |
| 상세 | `ui.ItemDetail`, `ui.ColumnsMenu` | 아이템 하나·두 판 |
| 분할 | `ui.SplitMenu`, `ui.ListSplitMenu` | 목록에서 고른 항목의 동작을 같은 창 오른쪽에(연구, 세이브 선택) |
| 트리 | `ui.TreeMenu` | 선후 관계가 있는 노드(발전과제). 노드 글은 호버, 누르면 상세 폼([advancement-tree.md](advancement-tree.md)) |
| 탭 | `ui.Tab` | 같은 창의 서로 다른 **보기**를 오가는 화면: 생산 통계(생산·에너지·정지), 도감(검색·체·가공·몬스터·식물), 칭호·치장(칭호·이름 색·업적). 탭은 위쪽 줄에 모든 쪽에 보이고 아이콘 12px + 3글자 안팎의 글이다(탭 폭 52px, 창 폭 280px 에 다섯 개) |
| 쪽 넘김 | `ui.Pager` | 긴 목록을 나눌 때. 모든 쪽 넘김이 같은 글("이전 쪽 (1/3)")·같은 아이콘·같은 자리(아래 동작 줄) |
| 뒤로 / 도움말 | `ui.Back`, `ui.Help` | 제목 막대의 닫기 왼쪽 작은 버튼. 뒤로 가기는 한 단계 위(대부분 카드 메뉴)로 간다 |

- 탭과 카드를 섞지 않는다: **갈래를 고르는 것은 카드, 한 화면의 보기를 바꾸는 것은 탭**.
- 쪽 넘김은 탭이 아니다. 탭 줄에는 보기 탭만 둔다.
- 입력은 `ui.Input`(한 줄), `ui.Amount`(수)로 한다. 검색은 입력 → 결과 칸 격자 순서다(스토리지 목록, 도감).

## 화면 제목

메뉴 아래로 한 단계 들어간 화면의 제목은 `ui.SubTitle(상위, 하위)` 로 "상위 · 하위"다(도감, 장비 제작대, 칭호·치장).

## 탭 모양

탭은 게임 탭처럼 보인다: 회색으로 낮게 놓이고(`tab`), 포인터가 올라오면 밝아지고(`tab_hover`), 선택된 탭은 한 칸 솟아 창과 같은 색으로 아래가 창 쪽으로 열려 있고 글이 어둡다(`tab_on`). 텍스처는 `go run ./tools/uitextures`(없는 것만 만든다, `-f` 는 모두)가 만들고, 모양은 `df_form.json` 의 `tab_button` 이다.

## 칸과 아이템

- 아이템 칸은 어두운 칸(`slot`)에 아이템 그림, 오른쪽 아래 개수, 호버(엔진 툴팁)로 이름·설명. 개수는 1만부터 `12k`.
- 등급이 있는 아이템은 칸 뒤 색 배경과 이름 색, 단계는 왼쪽 위 점, 문제는 빨간 느낌표 배지(기계 정보 아이콘)로 보인다([slotdeco.md](slotdeco.md)). 같은 규칙이 가방·상자·기계 창·인벤토리 보기에 한꺼번에 적용된다.
- 기계 창은 제목 줄 오른쪽에 모두 넣기·모두 꺼내기·정보 아이콘이 나란히 있다([machines.md](machines.md)).

## 성능 규칙

칸·버튼이 한 화면에 수십 개를 넘지 않게 서버가 쪽을 나눈다(칸 격자 한 쪽 44칸, 도감 식물 33칸). 칸마다 컨트롤을 늘리는 장식은 먼저 열림 시간을 잰다.

## 창의 입체감

창 그림(`panel`)이 위·왼쪽 흰 선과 아래·오른쪽 어두운 선을 직접 갖고 있어 창이 떠 보인다(`panel_bevel` 은 비어 있다). 모든 테마 폼이 `df_form.window` 를 쓰므로 한 곳이다.

## 개선 후보

| 후보 | 내용 |
|---|---|
| 상자 창의 이름 검색 | 인벤토리 보기에는 제목 줄 검색 칸이 있다(입력과 맞지 않는 칸은 어두워짐). 다른 상자 창은 칸 수가 적어 두지 않았다 |

## 창 겉모양(게임 기본 화면 기준)

- 창과 탭의 모서리는 둥글다: 모서리 세 픽셀을 비우고 계단 모양으로 검은 선을 잇는다(`tools/uitextures` 의 `roundCorners`). 창은 아홉 조각(모서리 4px)이다.
- 제목은 막대 없이 창 위 가운데에 쓴다. 도움말(?)·뒤로·닫기는 창 오른쪽 위 모서리 위에 붙은 어두운 둥근 막대(바닐라 `toolbar_background`)에 바닐라 닫기·도움말 그림과 흰 화살표로 둔다. 틀은 없고 포인터가 올라오면 칸이 밝아진다(`icon_button`, `help_button` 의 기본 그림이 `clear`).
- 탭은 창 위 왼쪽 가장자리에 붙는다(`df_form.window` 의 `tabs_top`, 폼마다 안쪽에 두지 않는다). 연구 분할 화면은 왼쪽 판 안에 자기 탭을 두므로, 세이브 선택은 탭이 없으므로 `$df_tabs: df_form.no_tabs` 로 끈다.

- 카드(`card_button`)의 아이콘은 30px 이고 카드 가운데에 놓인다(이름은 아래).
- 뒤로 버튼은 픽셀 꺾쇠 그림(`chevron_left`)이고, 호버·누름은 닫기 버튼처럼 테두리 없는 회색 정사각형(`hover_flat`, `press_flat`)이다.
- 컨트롤 막대는 창 뒤(레이어 -2)에 그려지고 창의 오른쪽 가장자리에 딱 붙으며 아래 3px 이 창 뒤로 들어가고 오른쪽 끝은 창과 같다(offset 0).
- 창 안쪽 위 여백은 45(제목 아래 내용까지), 아래 여백은 6, 컨트롤 막대는 높이 25(안쪽 글자·아이콘 크기는 그대로)이다.
- 폼 뒤 화면은 바닐라처럼 어둡게 한다: 창(`df_form.window`, 발전과제 창)의 첫 자식 `dim` 이 `textures/ui/Black` 4000×4000 을 투명도 0.5 로 깐다(바닐라는 `screen_background` 를 0.4). 본문이 비어 있으면 본문 칸이 접힌다(`#form_text` 가 빈 글이면 숨김).

## 모든 폼의 기본 형태

창 안쪽 위·아래 여백(45·6), 컨트롤 막대(높이 25, 버튼 폭에 맞춤), 주변 어둡게(`Black` 0.5)는 기본이다. `df_form.window` 를 쓰는 모든 폼과 발전과제 트리 창(`tree_form`)이 `df_form.control_bar` 와 `dim` 을 같이 쓴다. 새 폼은 `df_form.window` 를 쓰고, 자체 창이 필요하면 `control_bar` 와 `dim` 을 넣는다.

## 폼 열림 애니메이션

처음 여는 폼은 창이 아래에서 올라오며 나타나고(`window_slide_in` 36px + `window_fade_in`, 0.18초), 버튼을 눌러 다시 보내는 폼(탭·쪽 넘김·뒤로 등)은 바로 나타난다. 제목 앞 `ui.NoAnimToken`(`§d§f§n§r`) 이 있으면 `server_form.json` 이 같은 폼의 정지 판(`$df_anims: []`)을 보여 준다. `ui.Menu` 가 버튼 누름 직후(400ms 안)의 폼에 이 표식을 붙인다(`resent`). 발전과제 트리 창은 `tree_slide_in`(최종 위치 오프셋 18)을 쓴다. 입력 폼(`custom_form`)은 기본 애니메이션이 그대로다. 애니메이션 모양은 `window_slide_in` 등 세 정의만 고치면 된다.
