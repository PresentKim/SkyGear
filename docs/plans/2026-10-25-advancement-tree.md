# 설계·계획: 발전과제 화면과 트리 재구성

브랜치 `dev`(작업은 `refactor/advancements` 에서 하고 `dev` 에 합침). 오케스트레이터: 사람(이 문서 승인 후 빌드).

## 목표
1. 발전과제 화면(DDUI 퀘스트 책)이 다른 창과 같은 크기·컨트롤 막대로 서고, 모바일에서도 툴팁이 읽힌다.
2. 발전과제를 얻는 방식으로 묶은 챕터로 다시 놓아, JE 모드팩 퀘스트 책처럼 흐름이 한눈에 보이고 모든 노드가 유기적으로 이어진다.
3. 모든 발전과제를 처음부터 공개한다. 선행이 끝나지 않은 노드는 조금 더 어둡게 그린다.

## 결정 사항(사용자 답)
- 챕터: 얻는 방식(손작업·체·농사와 배럴·기계·합금과 유체·사냥·장비·마법)과 프로젝트·부가 기능. 선행이 다른 챕터에 있어도 과제를 옮기지 않고 입구 표시로 잇는다.
- 배치: 자동 배치를 개선한다(좌표를 손으로 적지 않는다).
- 순서: 조건을 채우면 선행과 상관없이 바로 달성한다. 선행을 자동으로 달성 처리하지 않는다.
- 선행: 한 노드가 여러 선행을 가질 수 있다.

## A. 화면 레이아웃(DDUI, `common/ui/quest.go`, `common/packs/oreui/hbui/oui-mc.css`·`oui-ddui.js`·`oui-ddui.css`)
| 문제 | 원인 | 고침 |
|---|---|---|
| 창이 너무 큼 | `.mc-quest-window` 가 화면의 82%(`oui-mc.css:839`), `l.size = "quest"` | 다른 창과 같은 326×166 GUI px(`l.window` 의 `windowW/H`, 최대 96vw·96vh). `l.size` 도 공통 값으로. 챕터 열 폭을 줄여 판을 넓힌다(약 80u) |
| 컨트롤 막대 위치 | 막대를 제목 줄 안에 넣고(`quest.go:131-138`) `.mc-quest-head .mc-toolbar` 로 덮어씀(`oui-mc.css:926-944`) | `l.window` 와 같은 구조로: 막대를 창의 직속 자식으로 두어 창 오른쪽 위 바깥에 뜨게 한다. 덮어쓰는 규칙과 챕터 열의 중복 제목을 지운다 |
| 모바일 툴팁이 작음 | `#oui-tip` 글자 0.75rem·최대 폭 18rem, 글꼴 없음, 화면 끝 처리 없음(`oui-ddui.css:325`) | 글자 1.4rem(Minecraft 글꼴), 여백 0.7rem, 최대 폭 50rem. 터치를 본 뒤(`touchSeen`)에는 한 단계 더 크게. `showTip` 에서 화면 안으로 끌어온다. 모든 DDUI 툴팁에 함께 적용된다 |

JSON UI 트리(`ui.TreeMenu`, `/uimode` 로 JSON 을 고른 플레이어)는 크기 문제가 보고되지 않아 데이터 변경(아래 B)에 맞추는 것만 한다.

## B. 데이터 모델(`internal/games/dragonfactory/advancement.go`)
- `Parent string` → `Parents []string`(여럿). 챕터를 계산하지 않고 `Chapter` 필드로 적는다(`advTabRoots`·`advTabFind` 를 없앤다).
- **상태**: 달성(초록) / 열림(선행을 모두 달성, 지금처럼 밝게) / 잠김(선행이 남음, 조금 어둡게, 이름·아이콘·힌트는 보인다). "???"·숨김을 없앤다.
- **달성**: 조건(아이템·연구·이벤트)을 채우면 잠김이어도 바로 달성한다. `completeAdvancements` 의 선행 자동 달성을 없앤다. 이미 저장된 달성은 그대로 둔다.
- **퀘스트 창 다음 할 일**(`nextAdvancement`): 추적 중인 노드, 아니면 목록 순서로 첫 **열림** 노드. 목록은 챕터 순서 → 챕터 안 흐름 순서로 다시 놓는다.
- **세이브 호환**: ID 는 그대로 둔다(달성 맵·추적이 ID 키). 이벤트 ID 와 업적 연결(`advAchievements`)도 그대로. 새 노드는 새 ID 로 더한다. `achAllAdv` 는 지금처럼 개수 비교.

## C. 자동 배치 개선(`advancementLayout`)
- 챕터마다 고정 배치(모두 공개라 자리가 바뀌지 않는다).
- 열 = 챕터 안에서 선행을 따라간 **가장 긴** 깊이(여러 선행이면 가장 늦은 선행 다음 열).
- 행 = 열마다 선행들 행의 평균(무게중심)으로 정렬하고 두 번 오가며 다듬어 선이 덜 엇갈리게 한다. 같은 자리는 아래로 민다.
- **다른 챕터의 선행**은 첫 자식 바로 앞 열에 작은 **입구 표시**(그 선행 과제의 아이콘과 챕터·노드 이름 툴팁, 누르면 그 챕터로 이동)로 그리고 선을 잇는다. 그래서 선 없는 가짜 뿌리가 없다.
- 한 열보다 먼 선은 사이 열마다 빈 경유 칸을 두고, DDUI 선은 열 사이 틈에서 꺾어(선행마다 다른 세로 길) 노드 위를 지나거나 다른 선과 포개지지 않게 한다.
- DDUI 는 선행마다 선을 긋는다. JSON UI 트리(격자 버스 선)는 첫 선행 선만 긋고, 나머지 선행은 툴팁에 적는다. 한 챕터가 11×21 격자에 들어가는지 테스트가 계속 검사한다.

## D. 챕터와 연결
챕터는 과제의 것을 얻는 방식으로 묶는다(`internal/games/dragonfactory/advancement.go` 가 기준).
1. **시작**(손작업): 나무·판자·조합대·연구대·첫 연구, 돌멩이·조약돌, 나무 도구·상자, 돌 도끼·섬유·실·활, 망치·자갈·먼지, 화로·횃불·유리, 묘목 키우기, 첫 청크.
2. **체**: 체·체질, 광석 조각 → 광석 블록 → 광석 가루, 철·구리·주석·납·금·은·니켈, 다이아·네더라이트 메쉬, 몬스터 에센스.
3. **농사와 배럴**: 퇴비통·배럴·나무 양동이·점토(배럴 + 먼지), 씨앗(체질)·밀·빵·황금 당근, 양동이·돌 배럴·용암·흑요석, 마녀 물.
4. **에너지와 자동화**: 발전기·첫 기계·에너지 도관·호퍼·아이템 도관·나무 호퍼·아이템 흡입기, 자동 채굴기·분쇄기·자동 체·전기 화로·수확기·벌목기·레드스톤·자동 제작기, 서랍·서랍 업그레이드·스토리지, 실험실과 정수들, 에너지 셀, 도관 강화, 생산 통계, 기계 강화·설정 복사기.
5. **합금과 유체**: 합금로·청동·일렉트럼·인바·강철, 액체 도관·유체 탱크·광석 세척기·도가니·용암 발전기.
6. **사냥**: 몬스터 시뮬레이터·뼈·슬라임·엔더 진주·블레이즈 막대·가루·엔더의 눈·엔더 상자, 차원 게이트·첫 사냥·웨이브 1·3·5·8.
7. **장비**: 철 곡괭이·철 갑옷·가위·모루·구리 도구, 다이아 도구·갑옷, 도구 제작대·도구 제작·개조·레벨.
8. **마법**: 마법 씨앗·꽃·광석·보석·에센스 꽃과 수확, 염료·색유리, 마법 체.
9. **프로젝트**: 산업 ← 도관 3단계·스토리지 컨트롤러·자동 제작기·용암 발전기, 사냥꾼 ← 웨이브 5·도구 제작·다이아 갑옷·블레이즈 막대, 식물학자 ← 에센스 꽃·염료, 용 ← 세 프로젝트, 용의 알.
10. **부가 기능**: 청크 8·16, 랜턴·석재 절단기·용광로·나침반·다이아 블록·사암·석영·자수정, 분실물·요정의 선물·도감 즐겨찾기.

## E. 빌드 계획(태스크)
superlite subagent-driven-development 로 실행. 기존 인터페이스(`state.Advancements` 키, 이벤트 ID, `advAchievements`, `/dfadmin advance`)는 동결.
1. **레이아웃(DDUI)**: 창 크기·컨트롤 막대(`quest.go`, `oui-mc.css`). 팩 검사기·`common/ui` 테스트.
2. **툴팁**: 크기·글꼴·화면 안 고정·터치 확대(`oui-ddui.css`·`oui-ddui.js`).
3. **데이터 모델**: `Parents`·`Chapter`, 상태 계산(잠김 표시·모두 공개), 선행 자동 달성 제거, `nextAdvancement`. 테스트(`advancement_test.go`) 갱신.
4. **자동 배치**: 가장 긴 깊이·무게중심 정렬·입구 표시(`advancementLayout`, `showQuestBook`, `QuestNode.Deps` 여럿, JSON UI 첫 선행). 겹침 없음·격자 안에 듦 테스트.
5. **트리 재배치**: D 의 챕터·연결·순서, 챕터 이름·아이콘(`ko.json`/`en.json`). 진행 순서 테스트(선행이 앞에, 챕터 순서) 갱신.
6. **새 노드**: D-8 의 새 발전과제, 이름·힌트 글, 이벤트 호출. `TestAdvancementGuides` 통과.
7. **문서·시나리오**: `docs/tech/advancement-tree.md`, `docs/tech/oreui.md`(창 크기 예외 삭제), `docs/design/05·10`, `TODO.md` 실기 항목, `spike/scenarios/advancements.sh` 갱신.

## Acceptance checks
1. DDUI 발전과제 창이 도감·연구 창과 같은 크기이고, 닫기·뒤로 막대가 창 오른쪽 위 바깥(다른 창과 같은 자리)에 있다.
2. 모바일에서 노드를 처음 탭하면 뜨는 툴팁 글자가 창 글자만큼 크고 화면 밖으로 잘리지 않는다.
3. 왼쪽 챕터가 D 의 순서이고, 과제가 얻는 방식의 챕터에 있다(다이아 메쉬는 체).
4. 새 세이브에서도 모든 챕터의 모든 노드가 보인다. 선행이 남은 노드는 열린 노드보다 어둡고, 이름·힌트를 읽을 수 있다.
5. 챕터 안에 선 없는 노드가 없다(첫 노드와 다른 챕터에서 오는 입구 표시만 예외).
6. 잠긴 노드의 조건을 먼저 채우면 그 노드만 달성되고 선행은 달성되지 않는다.
7. 퀘스트 창은 첫 열린 노드를 보인다(새 세이브: 나무 얻기).
8. 기존 세이브의 달성·추적이 그대로 남는다.
