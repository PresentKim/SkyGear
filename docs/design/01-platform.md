# 01. 플랫폼: 접속 흐름 · 계정 · 세이브 · 인스턴스

## 1. 접속 흐름

```
접속 → (첫 접속) 서버 안내 → 로비
로비 → 세이브 슬롯 선택(1~3) → 인스턴스 입장
인스턴스 → /lobby 또는 메뉴 → 로비 (상태 저장)
```

1. **서버 안내**: 첫 접속 시 안내 폼(서버 소개, 기본 조작, 메뉴 여는 법)을 보여준다.
   이후에는 `/guide` 명령으로 다시 볼 수 있다. 안내 버전이 바뀌면 다시 노출한다. 로비 메인 메뉴는 싱글 플레이(내 세이브)·멀티 플레이(초대 코드 입력·받은 초대·참여 중인 세이브)·친구·칭호·치장·도움말 순이다.
2. **로비**: 모든 플레이어가 공유하는 허브 월드. 건축·전투 불가.
   로비 전용 인벤토리(메뉴 아이템)를 쓰며 인스턴스 인벤토리와 분리된다.
   - **게임 입장기 화면**: 로비는 걸어 다니는 곳이 아니라 메뉴다. 플레이어는 작은 하늘섬(풀 윗면, 흙·돌로 좁아지는 아랫면, 참나무, 꽃, 등불)에 서 있고, 카메라는 섬 남쪽 앞에서 섬을 비춘다. 화면이 멈춰 있지 않게 카메라는 섬 가운데를 바라본 채 앞쪽 다섯 지점을 14초씩 천천히 오가고(가감속), 캐릭터는 5~10초마다 나무·등불·꽃·하늘 쪽으로 고개를 돌리고 25~40초마다 손을 흔들거나 기지개를 켠다(팩 애니메이션 `animations/lobby.animation.json`, 그 플레이어 화면에만). 화면 왼쪽 위에 게임 아이콘과 이름, 그 아래에 메인 메뉴(큰 버튼 다섯 개: 아이콘·이름·꺾쇠)가 있다. 이름 틀은 로비의 모든 폼 뒤에도 그려지고(폼은 화면을 어둡게 하지 않는다), 메인 메뉴는 창 없는 폼이면서 HUD 에도 똑같은 그림으로 그려져, 폼을 닫아도 화면이 바뀌지 않는다. 로비에서는 다른 폼이 없을 때 늘 메인 메뉴가 열려 있다. 하위 화면을 닫거나 누른 뒤 다른 폼이 뜨지 않으면 메인 메뉴가 바로 다시 열린다. 메인 메뉴 자체를 닫으면(Esc) 1.5초 뒤에 다시 열리고, 그 전에 플레이어가 무엇이든 하면(클릭, 이동 키, 점프, 웅크리기, 사용 키, 핫바 칸 바꾸기) 바로 열린다. 로비에 도착하면(첫 접속은 서버 안내 뒤) 클라이언트가 로딩 화면을 닫은 뒤 메뉴 폼이 열린다.
   - 로비에서는 바닐라 HUD(핫바·체력·허기·조준점 등)를 모두 숨기고, 점프와 웅크리기 말고는 입력(이동·카메라·탑승)을 잠근다. 핫바 아홉 칸에는 모두 메뉴(나침반)를 두어 어느 칸을 들든 사용 키로 메인 메뉴가 열린다. 로비에서는 다른 플레이어가 보이지 않는다(자기 모습만 섬에 선다).
   - 로비에는 채팅이 없다: 접속 알림·안내 글을 채팅으로 보내지 않고, 플레이어도 채팅을 칠 수 없다(명령은 된다). 로비에서 알려야 할 일(받은 친구 요청·초대, 업적, 추방 등)은 토스트로 보인다.
   - 세이브에 들어가면 카메라·HUD·입력·틀·숨긴 플레이어가 모두 원래대로 돌아온다.
3. **세이브 선택**: 계정당 세이브 슬롯 3개. 한 화면에 왼쪽 슬롯 목록, 오른쪽 고른 슬롯의 동작. 열면 첫 세이브가 골라져 있다(세이브가 없으면 아무것도 고르지 않는다).
   - 슬롯 줄: 이름과 그 아래 일차·플레이 시간·만든 날. 이미 고른 줄을 눌러도 화면이 닫히지 않고 그대로 남는다.
   - 빈 슬롯: 누르면 바로 이름 입력 → 만든 세이브가 골라진 채로 목록으로 돌아온다(입장은 따로). 이름 입력 폼은 닫기나 그 폼의 뒤로 버튼으로 세이브 선택에 돌아온다.
   - 사용 중 슬롯: 고르면 오른쪽에 입장 / 초대 코드(버튼에 코드가 보이고, 누르면 확인 뒤 새 코드) / 참여자(버튼에 인원 수) / 이름 변경 / 삭제(확인 2회)
   - 뒤로 버튼(로비)은 다른 화면처럼 창 오른쪽 위 컨트롤 막대에 있다.
   - 초대받아 참여한 다른 호스트의 세이브는 로비의 **멀티 플레이**에 있다. 호스트가 플레이 중일 때만 입장 가능.
4. **입장**: 호스트가 입장하면 인스턴스를 활성화하고 이동한다. 입장·로비 이동 직후에는 목적지의 청크가 도착할 때까지 몸을 붙잡아 두고, 도착한 뒤에 움직일 수 있게 한다. 저장된 위치가 허공이면 가장 가까운 바닥이나 대체 지점(섬 시작 위치·로비 시작 위치)에 내려놓는다.
5. **채팅과 접속 알림은 세이브 안에서만**: 채팅은 같은 세이브(인스턴스)에 있는 플레이어끼리만 주고받는다. 서버 전체의 접속·퇴장 알림은 없고, 세이브에 누가 들어오거나 나가면 그 세이브의 다른 플레이어에게만 알린다.

### 게임 종류
- 플랫폼은 여러 게임 종류를 지원하는 구조로 개발하지만, **현재 사용자에게 게임 선택 단계를 보여주지 않는다.**
  유일한 게임 종류는 **드래곤팩토리**이며 세이브 슬롯은 게임 종류별로 구분해 저장한다(추후 게임 추가 대비).

## 2. 데이터 범위

| 범위 | 예시 |
|---|---|
| 계정 | 치장, 칭호, 친구 목록, 설정, 안내 확인 버전, 누적 통계 |
| 세이브(공유) | 월드 블록, 연구, 발전과제, 소유 청크, 작물·배럴·퇴비통 상태, 웨이브 진행, 인스턴스 시간, 분실물 |
| 세이브 × 플레이어 | 인벤토리, 위치, 체력/허기, 경험치, 개인 통계 |

- 플레이어가 인스턴스를 나갈 때(로비 이동, 접속 종료, 인스턴스 종료, 서버 종료) 세이브 × 플레이어 상태를 저장하고,
  들어올 때 복원한다. 처음 들어오는 세이브면 게임의 초기 지급품을 준다.

## 3. 세이브와 인스턴스

인스턴스는 **싱글 플레이 게임 같은 경험**을 위한 것이다. 시간은 호스트가 있을 때만 흐른다.

- 세이브는 **호스트 계정**에 속한다. 게스트는 호스트의 세이브에 참여할 뿐 자기 슬롯을 쓰지 않는다.
- **활성화**: 호스트가 입장하면 인스턴스(월드)를 로드하고 인스턴스 시간이 흐르기 시작한다.
- **비활성화**: 호스트가 인스턴스를 나가면(로비 이동·접속 종료) 인스턴스를 종료한다.
  - 남아 있던 게스트는 상태를 저장한 뒤 로비로 이동시키고 안내 메시지를 보낸다.
  - 세이브를 저장하고 월드를 언로드한다. 인스턴스 시간과 모든 타이머(작물, 배럴, 요정 방문 등)는 멈춘다.
- **게스트는 호스트 없이 입장할 수 없다.**
- **공동 호스트**: 호스트 대신 인스턴스를 활성화할 수 있는 등급. 참여자 권한을 `host / cohost / guest` 등급으로 저장하고 "인스턴스 활성화 가능 여부"를 등급으로 판단하는 구조를 갖춘다.

### 인스턴스 시간
- 세이브마다 **인스턴스 시간**(활성화되어 있던 누적 시간)을 기록한다. 게임 내 주기(작물 성장, 배럴, 분실물 보관 기간 등)는 모두 인스턴스 시간 기준이다.
- **인스턴스 하루**: 인스턴스 시간을 일정 길이로 나눈 단위. 세이브에 **경과 일수**로 기록하고, 하루가 넘어갈 때 일 단위 갱신을 처리한다.
- 하루의 길이는 설정값이다(`platform.toml`, 현재 20분).

### 활성 영역
- 활성화된 인스턴스는 섬의 **소유 청크 전체**를 로드하고 틱을 돌린다(플레이어가 멀리 있어도 공장이 동작).
- 소유 청크 수는 서버 부하와 직결되므로 섬 확장은 비용을 들여 단계적으로 연다([02-dragonfactory.md](02-dragonfactory.md) §8).

## 4. 친구 · 초대

### 친구
- `친구 요청 → 수락` 방식의 상호 관계. 오프라인 플레이어에게도 요청 가능(다음 접속 시 알림).
- **친구 화면**(로비 메인 메뉴의 친구, 세이브 안의 게임 메뉴 친구 카드, `/friends`): 세이브 선택과 같은 모양으로 왼쪽 목록, 오른쪽 고른 줄의 동작. 위쪽 탭은 친구 · 받은 요청(개수) · 차단.
  - 친구 탭: 맨 위에 친구 추가 줄(누르면 바로 이름 입력), 그 아래 친구(접속 중인 친구가 먼저, 줄 아래에 로비 / 세이브 플레이 중 / 오프라인). 친구를 고르면 친구 삭제 · 차단(둘 다 확인, 취소하면 화면으로 돌아온다).
  - 자기 세이브 안의 호스트: 맨 위에 초대 코드 줄(코드가 줄에 보이고 새 코드 버튼), 접속 중이고 그 세이브에 없는 친구를 고르면 세이브에 초대.
  - 받은 요청 탭: 수락 · 거절 · 차단. 차단 탭: 차단 해제.
- **멀티 플레이 화면**(로비): 같은 모양으로 맨 위에 초대 코드 입력 줄(누르면 바로 코드 입력), 그 아래 받은 초대(남은 분), 참여 중인 세이브(호스트 · 플레이 중/접속 안 함 · 일차). 초대는 참여 · 거절, 세이브는 입장(호스트가 플레이 중일 때) · 탈퇴.
- 차단: 차단한 플레이어의 친구 요청·초대를 받지 않는다.

### 인스턴스 초대
1. **초대 코드**: 세이브마다 6자리 코드(예: `K7Q2MX`, 헷갈리는 0/O/1/I 제외). 로비에서 코드를 입력(메뉴 또는 `/join 코드`)하면 참여자로 등록되고, 호스트가 플레이 중이면 바로 입장.
   호스트가 재발급하면 이전 코드는 무효.
2. **친구 초대**: 자기 세이브 안의 친구 화면에서 온라인 친구를 골라 초대 → 받은 쪽은 로비에서 바로 뜨는 창에서 참여(즉시 입장)하거나 나중에(멀티 플레이에 남음).

- 한 번 참여한 게스트는 세이브의 **참여자 목록**에 남는다.
- 세이브당 최대 인원: 초안 10명(호스트 포함).

### 참여자 관리
- 호스트는 참여자를 추방할 수 있고, 게스트는 스스로 탈퇴할 수 있다.
- 추방·탈퇴한 플레이어의 세이브 × 플레이어 데이터(인벤토리 등)는 **삭제하지 않고 세이브에 보관**한다.
- **인벤토리 열람(InvSee)**: 호스트는 현재 참여자와 추방·탈퇴한 플레이어를 포함한 **모든 플레이어의 인벤토리를 확인하고 꺼내거나 넣을 수 있다.**
  대상이 그 세이브 안에 있으면 실시간 인벤토리를, 아니면 저장된 인벤토리를 편집한다(편집 중에는 대상이 입장할 수 없음).
  엔티티 상자 화면에서 인벤·핫바·갑옷·보조손·엔더상자를 직접 옮긴다. 같은 세이브 안의 대상은 실시간, 그 외에는 저장된 상태를 잠그고 편집한다([chestui](../tech/chestui.md)).
- 호스트 메뉴: 로비의 싱글 플레이(세이브 선택) → 초대 코드 / 참여자, 세이브 안에서 게임 메뉴의 친구 카드(`/invite`), `/members`. 참여자 관리도 왼쪽 참여자 목록(호스트, 탈퇴·추방됨 표시), 오른쪽 인벤토리 보기 · 추방이다.
- **플레이어를 웅크린 채 우클릭**하면 그 플레이어가 선택된 참여자 관리가 바로 열린다(인벤토리 보기·추방, 같은 세이브에 있으면 그 플레이어에게 이동·내 곁으로 부르기). 오프라인 참여자는 목록에서 고른다. 서버 운영자(`platform.toml` `[Admin] Operators`)는 자기가 들어가 있는 어느 세이브에서든 호스트처럼 참여자를 관리한다(웅크린 우클릭, `/members`).
- 운영자는 테스트용으로 다른 플레이어의 세이브를 자기 빈 슬롯에 복제한다: `/copysave <플레이어>` 가 그 플레이어의 세이브(슬롯·이름·일차)를 보이고, `/copysave <플레이어> <슬롯>` 이 그 세이브를 첫 빈 슬롯에 "<이름> (복제)" 로 만든다(`internal/platform/copysave.go`). 월드 폴더, 게임 상태, 시계, 원래 호스트의 플레이어 상태(인벤토리 등)가 복제되고, 운영자 혼자 호스트다. 열려 있는(활성) 세이브는 월드 파일이 바뀌는 중이라 복제하지 않는다.
- 친구 초대는 10분 동안 유효하다. 로비에 있으면 바로 수락 창이 뜨고, 아니면 로비 멀티 플레이 목록에 남는다.

## 5. 계정 요소

- **칭호**: 업적·이벤트로 획득, 채팅/이름표 앞에 표시. 하나를 장착. 닉네임 앞에 붙이고 다닐 수식어("흙을좋아하는 Hana")로 쓰고, 업적의 조건이나 숫자를 알려 주지 않는다.
- **치장**: 이름표 색, 채팅 색, 파티클 등 밸런스에 영향 없는 요소.
- 구현:
  - 업적은 계정 단위로 한 번씩 얻는다(`internal/account`, DB `achievements`). 게임이 업적을 등록하고 조건이 되면 준다(`account.Grant`).
  - 업적 대부분이 칭호를 하나씩 연다. 로비 메인 메뉴와 세이브 안 게임 메뉴(또는 `/title`)의 칭호·치장에서 칭호 하나와 이름 색을 고른다. 채팅(`<[칭호] 이름> …`)과 이름표에 보인다.
  - 이름 색: 기본·노랑·하늘·초록은 처음부터, 금색·분홍은 업적 3개, 빨강·파랑은 6개, 이후 12·20·30·45·65·90·120·160개에서 짙은 초록·짙은 청록·보라·구리·에메랄드·다이아몬드·자수정·네더라이트가 열린다.
  - **카운터 업적**: 게임이 행동을 키(`account.Count`)로 세고, 키마다 단계(`account.RegisterCounter`)를 두어 첫 번째와 누적 횟수에서 업적·칭호를 준다. 횟수는 계정 단위로 메모리에 쌓였다가 DB `counters`에 묶음으로 저장된다(20초마다, 접속을 떠날 때, 종료할 때). 업적에는 분류(group)가 있어 칭호 고르기와 업적 목록이 분류별로 나뉘고, 못 얻은 카운터 업적은 지금 횟수/목표 횟수를 보여 준다. 멀티플레이가 필요한 업적은 두지 않는다.
  - 드래곤팩토리 업적(`achievements.go`): 첫 연구, 첫 기계 설치, 청크 10개. 카운터 업적은 `achcatalog.go`(키, 분류, 단계)에 있고 글은 `ko.json`의 `achievement.df_<키>_<횟수>.*` 에 있다. 분류는 손작업·농사와 식물·체질·기계와 공장·에너지·장비·전투·성장·섬·수집·생활. 기계와 식물이 스스로 한 일은 섬에 접속 중인 모든 플레이어에게 세어진다. 수집 분류는 아이템을 처음 가지는 순간(`haveCatalog`)에 준다.

### 5.1 설정

- 플레이어마다 켜고 끄는 설정은 계정에 저장된다(DB `account_settings`, `internal/account/settings.go`). 게임과 플랫폼이 설정을 등록하고(`account.RegisterSetting`) 그 동작을 하는 곳에서 읽는다(`account.On`).
- 설정 화면은 세이브 안 게임 메뉴의 **설정** 카드와 `/settings` 로 연다. 설정마다 이름과 켜짐·꺼짐이 한 줄인 버튼이고, 누르면 바뀌고 화면이 그대로 다시 보인다. 뒤로 가기 버튼은 연 곳의 메뉴(세이브에서는 게임 메뉴, 로비에서는 메인 메뉴)로 돌아간다.
- 지금의 설정(모두 기본 켬, 광맥 캐기 대각선만 기본 끔):
  - 업적 달성: 화면 알림(토스트, 칭호 획득 줄 포함), 채팅 메시지(로비에서는 없음), 소리.
  - 발전과제(드래곤팩토리): 달성 화면 알림, 채팅 메시지, 소리, 화면 오른쪽의 발전과제 패널 표시.
  - 광맥 캐기 대각선 포함(드래곤팩토리, 철 망치를 들고 웅크려 허공을 써도 바뀐다).
  - 메뉴를 JSON UI 폼으로 보기(`/uimode` 와 같다, [oreui.md](../tech/oreui.md)).

## 6. 기간제 아이템

- 플랫폼 공용 기능. 기간은 **현실 시간으로만** 센다(만료 시각을 아이템에 기록). 서버·세이브·플레이어가 꺼져 있던 시간도 흐른다.
- 사용량으로 제한할 아이템은 기간제가 아니라 사용 횟수(내구도 등)로 만든다. 둘을 섞지 않는다.
- 만료되면 플레이어가 가진 것은 1초 안에 사라지고 알림을 받는다. 들고 쓰려 하면 동작이 취소된다. 상자 안의 것은 열 때 정리된다.
- 설명 줄의 만료 시각은 한국 시간으로 보여 준다. 알림은 사라질 때 채팅으로만 하고 만료 전 알림은 없다.
- 게임의 보관·가공은 아이템을 NBT 전체로 구분한다. 그래서 기간제 아이템은 다른 아이템과 섞이지 않는다.
- 기술 문서: [timed-items.md](../tech/timed-items.md).
