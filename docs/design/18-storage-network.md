# 18. 스토리지 망 (Refined Storage 풍)

> [08 §1](08-storage-gear-magic.md)의 서랍 스토리지 컨트롤러 다음 단계다. 수치는 모두 초안이며 [open-questions](open-questions.md)의 밸런싱 표를 따른다.

서랍 컨트롤러가 "서랍 여러 개를 하나로 묶는" 장치라면, 스토리지 망은 **디스크에 아이템을 담고, 단말에서 꺼내고, 수입·수출로 기계와 잇고, 패턴으로 자동 제작하는** 물류 시스템이다. Java판 Refined Storage(RS)의 흐름을 따르고, 성능은 Applied Energistics 2(AE2)가 쓰는 방식을 참고해 새로 만든다.

## 2. 블록과 아이템

| 이름 | 종류 | 하는 일 |
|---|---|---|

| 망 케이블 | 블록 | 장치끼리 잇기만 한다. 장치도 서로 붙으면 이어진다 |
| 디스크 드라이브 | 블록 | 저장 디스크 8장을 꽂는다. 우선순위(-10~10)를 정한다 |

| 패턴 인코더 | 블록 | 빈 패턴에 조합법을 새긴다. 제작대 조합법(연구로 열린 것)을 고르거나, 처리 패턴(재료 → 결과를 직접 놓아 정함)을 만든다 |

서랍 스토리지 컨트롤러와 스토리지 링크는 그대로 둔다. 서랍 망을 스토리지 망에 이으려면 외부 저장소의 앞면을 서랍 컨트롤러(또는 서랍)에 대면 된다.

## 3. 망 구성

- 망은 컨트롤러에서 시작해 면이 맞닿은 케이블과 장치를 따라간 집합이다. 한 망에 컨트롤러는 하나다. 컨트롤러가 둘 닿으면 둘 다 꺼지고 단말에 "컨트롤러가 둘" 이라고 보인다.
- 장치 수 상한 512. 넘으면 망이 꺼진다.
- 전력: 컨트롤러 기본 8 RE/t + 장치마다 1 RE/t(디스크 드라이브 2, 자동 제작 장치 4). 버퍼가 비면 망이 꺼진다(아이템은 그대로, 넣기·빼기만 멈춤).
- 블록을 놓거나 부수면 그 칸에 닿은 망만 다시 계산한다(아래 §7-1).

## 4. 저장과 이동 규칙

- 넣기: 우선순위 높은 저장소부터. 같은 우선순위 안에서는 **이미 그 아이템을 가진 저장소**가 먼저, 그다음 빈 자리. 필터가 막는 저장소는 건너뛴다.
- 빼기: 우선순위 낮은 저장소부터(높은 우선순위 저장소에 모아 두도록).
- 디스크 내용은 세이브 문서에 디스크 ID별로 저장한다. 디스크 아이템은 ID와 쓴 양만 들고 있어 설명에 "1,234 / 4,096"을 보인다. 디스크를 빼서 다른 드라이브에 꽂아도 내용이 따라간다.
- 외부 저장소는 대상 칸의 내용을 주기적으로 읽어 바뀐 부분만 망 목록에 반영한다. 대상이 망 밖에서 바뀌어도(호퍼가 넣음 등) 다음 읽기에 맞춰진다.
- 수입기·수출기는 한 번에 8개, 쉬는 간격은 일이 있으면 4틱까지 줄고 없으면 64틱까지 늘어난다.

## 5. 단말 조작

서랍 컨트롤러의 목록 창과 같은 조작을 쓴다.

- 우클릭: 손에 든 묶음을 넣는다. 0.5초 안에 두 번이면 인벤토리도 모두 넣는다(망이 가진 종류만).
- 웅크려 우클릭: 목록 창. 한 격자에 개수 많은 순으로 보이고, 검색(초성 포함)과 정렬 버튼이 있다. 한 번에 최대 240칸까지 보여 주고, 넘으면 "검색으로 좁혀 보세요" 를 안내한다.
- 항목을 누르면 한 묶음을 꺼낸다.
- 패턴이 있는 아이템은 "제작 가능" 칸에 따로 보인다. 누르면 수량(1·8·64·직접 입력)을 고르고, 계산 결과(쓸 재료, 만들 중간 재료, **모자란 재료**)를 본 뒤 시작한다.
- 컨트롤 막대의 "제작 작업" 버튼은 진행 중인 작업 목록(진행률, 기다리는 재료)과 취소를 보여 준다.

## 6. 자동 제작

- **패턴**: 제작대 패턴은 조합법 ID를 담고, 태그 재료(아무 나무 판자 등)는 망에 있는 것 중 고른다. 처리 패턴은 재료 최대 9칸과 결과 최대 3칸을 담는다.
- **계산**: 요청한 아이템을 만드는 패턴을 찾고, 재료마다 "망 재고 → 이번 계산에서 만들어 둔 것 → 하위 패턴으로 만들기" 순으로 채운다. 하위 패턴이 실패하면 다음 패턴, 다음 대체 재료를 시도한다. 순환(패턴이 자기 결과를 다시 요구)은 오류로 알린다. 계산은 망 재고의 **사본**으로 월드 틱 밖에서 돌고, 결과를 틱 안에서 다시 확인해 시작한다.
- **실행**: 시작할 때 쓸 재료를 망에서 모두 빼 작업 보관함에 옮긴다(예약). 작업은 매 틱 할 수 있는 단계를 진행한다. 제작대 패턴은 자동 제작 장치마다 10틱에 1회, 처리 패턴은 대상 기계가 재료를 받을 때 1회분을 넣는다. 망에 들어오는 아이템 중 작업이 기다리는 결과는 작업 보관함으로 먼저 간다. 끝나면 결과와 남은 재료를 망에 돌려준다. 취소하면 보관함을 모두 망에 돌려준다(망이 가득 차면 컨트롤러 위에 떨군다).
- 한 망에서 동시에 8개 작업, 계산 한 번에 노드 100,000개까지.
- 작업은 세이브에 저장되어 서버를 다시 켜도 이어진다.

## 7. 성능 설계

AE2와 RS2가 큰 망에서 빠른 이유를 우리 구조에 맞게 옮긴다. AE2 쪽은 공개 문서에 나온 동작 방식만 참고한다.

1. **망 구성은 바뀔 때만 다시 계산한다**(AE2 그리드). 지금 서랍 컨트롤러는 50ms마다 다시 찾는다. 스토리지 망은 블록을 놓고 부술 때 그 칸 주변 망만 무효로 하고, 안전망으로 200틱마다 위치에 맞는 블록이 있는지 확인만 한다.
2. **합계 목록을 계속 유지한다**(RS2 RootStorage, AE2 저장소 캐시). 망 전체의 `아이템 → 개수` 를 넣고 뺄 때마다 고친다. 단말과 계산은 저장소를 하나하나 세지 않고 이 목록만 읽는다.
3. **아이템별 보유 저장소 색인.** `아이템 → 그 아이템을 가진 저장소` 를 유지해, 넣기·빼기가 모든 디스크를 훑지 않고 가진 곳부터 바로 간다.
4. **틱 수를 일에 맞춘다**(AE2 틱 관리자의 생각). 수입기·수출기·외부 저장소는 각자 쉬는 간격을 갖고, 일하면 짧게, 놀면 길게 바꾼다. 망은 다음에 깰 장치만 우선순위 큐에서 꺼내 부른다. 필요한 아이템이 들어오면 기다리던 수출기를 바로 깨운다.
5. **변화만 알린다.** 저장소 변화는 `(아이템, 차이)` 사건으로 듣는 쪽(단말 창, 작업, 수출기)에 간다. 단말 창은 바뀐 것이 있을 때만, 0.5초에 한 번까지 다시 그린다.
6. **계산은 사본으로, 틱 밖에서**(AE2 계산 방식). 계산이 길어도 월드 틱이 멈추지 않는다. 결과를 적용할 때 재고를 다시 확인하고, 모자라면 다시 계산한다.
7. **재료 예약.** 시작할 때 재료를 미리 빼 두어, 진행 중에 다른 작업이나 플레이어가 재료를 가져가 작업이 엉키는 일을 막는다.
